# App Review Risk Notes

> 現在の初版方針（2026-11-26）は無料・広告なし・Premiumなしです。品質改善の具体的な作業と証拠は [設計・実装指示書](store-release-polish/README.md) と [受入条件](store-release-polish/ACCEPTANCE.md) を参照してください。以下の広告・課金に関する検討は、将来それらを採用した場合のものと区別します。

## 1. mock Premiumを本番に残す
リスク:
- 購入処理が本物でない場合、審査で問題になりやすい

対策:
- 初版では広告・Premium・mock購入/復元の導線を無効のまま維持し、最終ビルドで表示されないことを確認する
- 将来Premiumを採用する場合は、モックではなく本番のStoreKit実装と検証が必要

## 2. 広告SDKのPrivacy申告漏れ

初版では広告SDKを追加しない。Capacitor等の既存依存については、最終ビルドの実態に即したPrivacy確認を行う。

リスク:
- 第三者 SDK のデータ収集申告漏れ

対策:
- SDK ドキュメントと Privacy Manifest を確認し、App Privacy に反映する

## 3. ATT未対応

初版はトラッキングなし。以下は将来、トラッキングを伴う機能を採用した場合の確認対象。

リスク:
- トラッキング広告や IDFA 利用時に ATT 未対応

対策:
- 非パーソナライズド広告を優先する
- 必要なら ATT を実装する

## 4. 誇大表現
リスク:
- 心理的効果や治療効果を示唆すると問題化しやすい

対策:
- メモ / 日記 / 記録アプリとして説明する

## 5. WebViewだけで低品質に見える
リスク:
- App Store で品質不足に見える可能性がある

対策:
- iOSらしい操作性
- オフライン保存
- 安定動作
- アイコン / スクリーンショット / UX品質を整える
