# 日英・混在文字の確認用データ

[round-2.json](round-2.json) は、調査第2回で作成した合成データ。24例の題名・本文、9件の検索期待値、6例の文字長、4例の復旧の意味、5例の日時書式を含む。既存作品や利用者の私的なメモの引用ではない。

**アプリの保存データではない。直接インポートしない。** テスト側で必要なNoteのid・createdAt・updatedAt・isFavorite等を作り、title/bodyを原文のまま使う。`ui_locales_to_check`をNote.localeへ移さない。

## 読み込みの約束

- JSONとして1回だけdecodeする。`\n`、`\t`、`\u200c`等は実際の改行・タブ・Unicode文字になる。
- fixtureの原文をtrim/NFC/NFKCで書き換えない。検索用比較は別の値で作る。
- `expected_under_proposed_policy`は採用する検索仕様の期待値。現在のアプリが合格したという記録ではない。
- `baseline_observation`と`baseline_commit`は旧コミット6b40f44での観察。現行4ec10d1の再現結果ではない。
- Unicodeの差を維持するためJSONは非ASCIIをエスケープしている。読み込み後の文字列で確認する。
- 外国語の文例は組版・入力・原文保持用。製品コピーとして母語話者校閲済みではない。

## 最新実装への読み替え

1. **MLT14〜16**：旧カードは空白を畳んでいたが、現在は`noteDisplay.ts`へ刷新済み。旧preview値を現行のスナップショット期待値にしない。採用した比較方針、現行の表示、原文保持をそれぞれ確認する。
2. **MLT23**：旧題名はtext input、現在はtextarea。旧観察の「text inputでは改行が除去される」を現行題名の仕様にしない。現在の題名・本文はtextareaのAPI valueと保持modelの境界を確認する。題名を本人が編集した場合の改行→空白は現行の単一行契約として維持するが、開くだけ・本文だけの編集・UI変更では書き戻さない。本文は編集時のLF方針を確認し、救済は保持modelを使う。
3. **MLT06**：現行ReadModeは空行へ表示用U+200Bを挿入する。提案する描画へ変更後、原文の空行と選択コピーへ装飾文字が混入しないことを確認する。DOM表示と保存文字列を同じものとして比較しない。
4. **MLT07〜08 / length_examples**：現行Segmenter不在fallbackのArray.fromは複合書記素の保証ではない。機能不在も含めて確認する。
5. **date_reference_examples**：Node/ICUの参考値。現在のアプリやiPhoneの出力保証ではない。日英初版へタイ語・和暦・アラビア数字の設定機能を追加する指示でもない。

## 不足分は目的を持って生成する

ML12の英語2000語、日本語2000字、長いURL、ML17の拡大画面、ML23の疑似翻訳、200前後の反復題名は、この24例だけで全部を満たしたとは扱わない。試験側で再現可能な合成データを用意する。必要なid・時刻や個数を明示し、利用者の実メモへ試験データを混ぜない。

期待値の検査は、製品関数の結果と原文の不変性、そして実機の表示・選択・入力を分ける。資料内のJSON整合確認をアプリの受入合格に数えない。
