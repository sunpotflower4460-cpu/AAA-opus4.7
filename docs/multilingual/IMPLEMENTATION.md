## 1. 目的と進め方

日本語・英語で、書く、保存する、読み返す、検索する、削除を戻す、保存失敗から原文を取り出す一連の体験を完成させる。現在の日本語版の保存保護と紙・筆あとを継承する。

この引継ぎは設計段階。実装開始時は最新mainと作業中のブランチを照合し、未コミット変更を消さない。広い変更が重なる場合は作業単位を分ける。旧監査のコードへ巻き戻す修正はしない。

| 段階 | 完成させるもの | 主なML |
|---|---|---|
| I0 | 最新差分・文言・状態・回帰の一覧 | 全項目の前提 |
| I1 | 日英辞書、言語解決、独立設定、安定Provider、native言語取得 | ML01〜09、20〜23、35〜36、42〜43 |
| I2 | 横書き・混在本文・入力・文字量・書体の適合 | ML10〜12、15、17〜19、29〜39 |
| I3 | 検索・日時・保存・復旧・削除・救済の全体統合 | ML04、07〜09、13〜16、25〜28、40〜41 |
| I4 | アプリ情報、native宣言、日英の掲載・支援準備 | ML21〜24、43〜44 |
| I5 | 同一コミットでの回帰・実機・校閲と残件の記録 | ML01〜44 |

I1の辞書・状態モデルが決まってから、I2とI3を担当ファイル単位で分担できる。App.tsx・NoteEditor.tsx・ReadMode.tsx・release.cssを複数担当が同時に別方針で書き換えない。I4の文章準備は並行できるが、実UI画像と対応言語の確定は実装後に行う。

## 3. I1 — 言語を変えても文章と状態が残る土台

### 責務の分割例

| 責務 | 候補ファイル |
|---|---|
| UiLocale / 設定 / Messages型 | `src/i18n/types.ts` |
| 同梱辞書 | `src/i18n/messages/ja.ts`, `en.ts` |
| 言語タグの照合 | `src/i18n/resolveLocale.ts` |
| 起動・実効言語・React供給 | `src/i18n/I18nProvider.tsx` と小さなbootstrap |
| 設定の読書き | `src/lib/uiPreferences.ts`等の小adapter |
| 現在のnativeアプリ言語 | 小さなread-only Capacitor bridgeとWeb側adapter |
| 例外時の最小文言 | Providerから独立した静的辞書 |
| 翻訳の意味と確認状態 | 小さなmetadata台帳 |

既存に同じ責務がある場合は統合する。大きな翻訳ライブラリ、外部翻訳サービス、独自の複雑なメッセージ構文は初版に導入しない。

### 3.1 辞書と状態

1. `Copy = typeof copy` の日本語リテラル型を英語辞書へそのまま適用せず、意味・引数を共通化したMessages型を用意する。
2. `En`接尾辞を本体UIの二重表示として残さず、実効言語の辞書を一つ選ぶ。筆あと名称やブランド固有語は採用した表記基準に従う。
3. 文全体を翻訳単位にし、件数はnoteCount等の意味付き引数で渡す。差し込み原文をHTML・翻訳キー・テンプレートとして再解釈しない。
4. 保存のreason、候補source/id、操作結果、notice kindを意味コードのまま保持し、描画時に訳す。ラベルの翻訳のために候補を再取得・再比較しない。
5. 翻訳状態の台帳を用意する。原文・訳文・引数・表示条件・操作結果の変更で要再確認にする。コードの意味の変更は実装者が台帳へ反映する。

### 3.2 設定と起動

- UI設定は `system | ja | en`。候補キーは `zanshin.prefs.ui-language.v1`。メモのprimary/backup/journalへ入れない。
- 既存の筆あと `zanshin.prefs.brush.v1` を保持する。初版は同じく小さな設定adapterを用い、Capacitor Preferencesへの一括移行や依存追加はしない。
- 独自の明示選択を最優先し、systemならnativeは現在のアプリ言語、Webは`navigator.languages`を照合する。日英完成版の未対応時はenへ戻す。
- native bridgeは `Bundle.main.preferredLocalizations` 等の公開されたread-only情報を返す。端末全体の言語と現在のアプリ言語を混同しない。Web用の言語列・地域書式用タグとは別の責務にする。
- bridgeの登録・読み出しをI1で実装し、純粋なresolverとadapterを試験できるようにする。ArchiveとOS設定の実際の挙動はI4/I5で確かめる。
- 起動時の読込みに失敗・遅延があっても、本文編集や救済を無期限に待たせない。bootstrapの完了・fallback・後着結果の採否を明示する。
- 明示選択後に遅い読込みを反映しない。連続選択の最後の値を保持し、古い保存完了が新しい選択を戻さない。
- 設定保存失敗時はこの起動中の選択を保ち、次回保持できない可能性を設定画面で伝える。本文の保存成否は変えない。
- 将来の未知の設定値は、実効fallbackと保存rawを分ける。旧版が読んだだけでrawをja/enへ上書きしない。本人が明示選択した時はその値を保存する。

### 3.3 安定したUIと救済

- App、Editor、RecoveryReview等へlocale依存keyを付けない。言語変更でreload・画面初期化・保存データ再読込をしない。
- 未保存本文、選択、IME、スクロール、戻り先、検索語、対象版、復旧候補、削除対象、Undo期限を保つ。
- 翻訳関数・辞書の参照変化を、保存や復旧probeの副作用の起点にしない。単にeffectの依存を消して問題を隠さず、意味コードと表示を分離する。
- `AppErrorBoundary`の救済を通常Providerの成功へ依存させない。安全な場所の解決済み言語と静的最小辞書から、原文の表示・コピーへ到達させる。
- メモの題名・本文・createdAt・updatedAt・isFavorite・未知フィールド・保護rawはUI設定だけで変更しない。
- 言語変更を原因とする追加の本文書込み・再serializeを発生させない。切替前の本文編集で必要だった自動保存、実行中の書込みとその結果反映は継続する。未保存編集を含む試験で総書込数ゼロを要求せず、同じ本文変更・時計条件で切替有無を比較する。
- 既存Note.localeは保持する。新規メモでは不要なja固定を省略する。UI言語をNote.localeへ書き込んだりvalidatorを拡張したりしない。

### 出口

言語解決、設定の失敗・競合、編集中・復旧中・削除中の言語変更、例外時の静的救済に再現可能な確認がある。英語未完の中間状態を製品の公開対応言語に追加しない。

## 4. I2 — 日英の読み方・文字・入力を完成させる

### 4.1 横書きと表示設定

- 現行ReadModeには横書き切替がない。今回、横書きで長文を末尾まで読める経路を実装する。
- 初版は共通の読書方向設定一つとし、候補キーを `zanshin.prefs.reading-mode.v1` とする。メモ別設定を新設しない。
- 既存の明示設定が最新コードに追加されていれば引き継ぐ。旧利用者・識別不能は従来の縦書きを保つ。新規導入を確定できた場合だけ、ja縦/en横の初期値を一度記録する。
- 0件だけで新規と判定しない。既存の保存検証結果と独立した初期化記録を使い、表示初期値のために保護データを直接再検査・再保存しない。
- UI言語だけの変更では縦横を変えない。明示切替では同じ文章付近へ移り、物理スクロール値を異なる軸へそのまま転用しない。
- 「左へ続きます」等は実際の方向・残りに対応させる。横書きで残さない。

### 4.2 混在本文と装飾

- 現行ReadModeの行span、空行に挿入するU+200B、lineWobbleと、新しい段落方向・原文選択の条件を照合する。
- 原文を一本のtext nodeで持つ `pre dir=auto` を優先比較候補にし、本文書体・余白・pre-wrapを明示する。採用は先頭LF、空行、字下げ、末尾LF、段落方向、選択・コピーの結果で判断する。
- 本人の文章へ装飾用の見えない文字を追加しない。既存の紙・筆あとを保持し、選択テキストと装飾を分ける。別方式を選ぶ場合も同じ受入条件を満たす。
- URL始まりの段落、自動折返しと明示改行、数字だけの行、抜粋の元段落の方向を区別する。
- 語中の一致部分をbdiで細切れにしない。強調を採用する場合は、元の字形形成・書記素・原文範囲を保つ。強調機能そのものは必須追加にしない。
- 全文の自動反転、一文字ずつの回転、保存時の全角化で縦書きを修正しない。

### 4.3 入力と文字数

- 題名は現行の高さ可変textareaを継承する。旧調査にある単一行inputへ戻さない。
- `maxLength=200`を見た目の200文字の保証として扱わない。200は書記素の目安として整理し、入力や既存題名を途中切断しない。
- IME中のslice、keydownだけによる全文再構成をしない。onChangeで受理した全文、確定、貼付け、音声入力、取消を確認する。
- 検索にはautoComplete/spellCheckと別にautoCorrect/autoCapitalizeの方針を明示する。本文・題名のOS支援は尊重し、アプリの自動訂正を追加しない。
- 表示上の識別可能性と、保存値が空か・未操作下書きかの判定を分ける。不可視文字だけの編集済み原文を自動削除しない。
- 現行のtextareaのAPI valueと保持modelの改行を区別する。題名は本人が題名を編集した時だけ、現行の単一行の意味（改行→空白）を維持する。開くだけ・本文だけの編集・UI変更で既存題名を整形しない。本文の編集時LF化の契約と、保持modelを使う救済コピーの入力元を明示する。

### 4.4 文字分割・lang・aria

- `noteDisplay.splitGraphemes`のArray.from代替だけで複合書記素を保護したことにしない。Segmenter不在時は、信頼できる分割処理または原文のJS切断を避ける表示で条件を満たす。
- データ保存へ正規化・trimを適用しない。書記素の境界処理も表示または計数の責務とする。
- htmlのlangは実効UI言語へ。本人の本文と言語が分かるlabel・補足を構造上分ける。placeholderだけで操作名を担わせない。
- 表示される名前とアクセシブルな名前を揃える。言語変更で全カードを大量に読み上げ直さない。
- 筆あと4種、現在の文字サイズの基点、release.cssの設計を継承する。英語UIを理由に本人の日本語メモの書体を変更しない。

### 出口

日英の長文・URL・詩・混在段落で末尾まで到達する。375×667、390×844、430px幅と文字拡大で主要操作が欠けない。Web確認とiPhone/IME/VoiceOver確認を分けて記録する。

## 5. I3 — 検索・件数・日時・保存と復旧を統合する

### 5.1 検索と抜粋

- 共通の比較方針をNFC → TABとUnicode Zsの連続を通常空白へ → localeに依存しない小文字化、とする。query外側のtrimは維持する。
- LF/CR/U+2028/U+2029を水平空白へ畳まない。アクセント除去、NFKC、全角半角、転写、翻訳検索は追加しない。
- `notesLogic.matchesNote`と`noteDisplay.matchExcerpt/getCardDisplay`で方針を揃える。結果に含まれるのに抜粋が無関係になる不一致を確認する。
- 比較後のindexを原文indexにしない。初版は一致した行の原文を出す方法でもよい。精密範囲を作る場合は位置対応を持つ。
- 比較結果でメモを重複排除しない。保存原文・時刻・印・未知フィールドを変更しない。
- 検索対象は題名・本文。日付印が検索対象であるかのように説明しない。

### 5.2 件数・日時

- 一覧、検索、復旧の0/1/2/11/1000件を別の文として扱う。メモ数と保存版の数を混同しない。
- date stampのYYYY.MM.DD、グレゴリオ暦、Latin数字を維持し、作成日の意味をariaで伝える。詳細日時は採用したlocale方針へ合わせる。
- 朝・昼・夕・夜を意味コードに分ける。時間区分は既存の5〜10時/11〜15時/16〜18時/19〜4時を維持する。
- UIのenを米国地域・タイムゾーンと同一視しない。表示文字列を保存・ソート・復旧比較のキーにしない。
- updatedAtは題名・本文・印を含むメモ全体の変更時刻。createdAtとの意味を維持する。R37の移行を追加しない。

### 5.3 保存・復旧・削除・救済

- 本体の現在版成功、古い版だけ成功、予備保存だけ失敗、読込不能、競合を意味で区別し、現在版を根拠に表示する。
- 0件の有効な保存版を「すべて削除済み」「候補なし」と断定しない。2箇所の既存コピーと周辺の引数・試験を更新する。
- View / Use / Save / Copyの効果を文言と一致させる。候補の閲覧で自動保存・自動merge・破棄を起こさない。
- source/kindから候補名を描画時に訳し、候補データ・選択id・確認対象を維持する。protected世代の番号は表示用引数として保つ。
- 復旧画面、CopyTextButton、例外時救済を日英化する。長文は保持modelの全文を渡し、表示抜粋だけをコピーしない。
- 明示コピーに渡した値の一致と、iOSの選択コピー・実クリップボードの挙動を別に確認する。
- Undoは既存の10秒・直近1件の契約を保つ。言語変更で期限を再設定しない。
- OS設定へ案内する機能を置く場合は、現在版の保存を先に確認する。失敗・競合中は原文取り出しと移動中止を示す。アプリ内切替はreloadしない。
- W1のRAM救済を永続下書きと説明しない。OSから直接変更してプロセスが終わった場合の未保存原文まで復元保証しない。
- 再起動後も、既存journal/nativeに残った未確定版は従来の復旧候補として保護する。RAMだけの原文を復元できないという制約を、永続層に残る候補まで破棄する理由にしない。

### 出口

通常時と異常時の全フローが両言語で意味を保つ。ML40の理解確認で「何が保存済みか」「押すと何が起きるか」「失う可能性」を説明できる。

## 6. I4 — native・情報ページ・掲載準備

2. 既存の管理されたURL・窓口を使用し、未確認の連絡先や返信時間を作らない。公開Issueへ本人のメモを必須添付にしない。

5. iOSの端末ja＋アプリen、端末en＋アプリja、独自override＋nativeメニューを実機で確認する。
6. 日本語・英語の名称、説明、更新情報、実UIのスクリーンショットと審査確認手順を用意する。画像へ未実装UIを描いて完成扱いにしない。
7. iosプロジェクトを削除・再生成しない。`npm run cap:sync:ios`の差分とArchiveの実値を照合する。

### 出口

## 7. I5 — 検証と引継ぎ

### 通常のコマンド

このリポジトリの現行スクリプトを使う。

```bash
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
```

最終的には `npm run check`（typecheck・lint・test・build）と既存CIの条件を満たす。既存CIの依存監査とiOS同期の整合確認も弱めない。環境に起因する起動障害を回避した別設定を使った場合は、元のコマンドの結果と別々に報告する。

今のpackage.jsonに翻訳検査専用コマンドはない。導入する場合は、実際のscript・型検査・検査対象を作ってから文書へ記載する。

### 必要な自動確認

- 言語解決、設定の遅延・失敗・最後の選択。
- 必須キー・引数・空訳・未確認状態と公開対象の整合。
- 言語変更時に本文・対象版・復旧候補・Undo期限を変えないこと。
- Unicode検索、水平空白、行境界、原文と抜粋の対応。
- Segmenter不在、題名の変換・貼付け、不可視題名と原文保持。
- 例外時にProvider不調でも保持modelから全文を取り出せること。

辞書の全文章を一文字ずつ写したテストを大量に作らない。意味・状態・原文を誤る境界を優先する。fixtureをNoteとして直接インポートせず、必要なid・時刻等をテスト側で作る。

### 実機・人の確認
