### 現行コードに合わせる注意点

- 題名は現在 `textarea` で、`maxLength={200}` が残る。旧単一行 `input` による改行除去は、過去の調査事実として区別する。
- 現在の `draftRescue.ts` は RAM 上の下書き救済である。再読み込み・終了・再起動後の未保存内容の永続化は実装済みではない。
- 0件を「すべて削除済み」と説明する文言は、`nativeRecoveryAlternativeNotice` と `recoveryReviewEmpty` の両方を確認対象にする。
- 現在の native 言語宣言は `ja`。日英が完成した版で初めて `ja` / `en` 宣言・`en` fallback へ変更する。
- 現在の `Intl.Segmenter` 不在時の `Array.from` はコードポイント単位。既存の R19 のテスト結果を、全環境での書記素分割成功と読み替えない。
- 英語公開には横書き読書が必要。従来の「日本語初版では条件付き・未採用」という R12 の記録はそのまま保存し、多言語版の追加要件として検証する。

## 2. 実施方法と状態

### 検証種別

| 記号 | 種別 | 記録する証拠 |
|---|---|---|
| M | 機械確認 | 型検査、辞書・台帳検査、ユニット/統合テスト、保存層の入力と結果。モック・故障注入の範囲を明記 |
| B | 実ブラウザ | 実描画、入力、選択、スクロール、文字拡大、Clipboard。DOM 属性やスクリーンショットだけで操作結果を推測しない |
| I | 実機 | iPhone の WKWebView、実 IME、VoiceOver、OS 言語・設定移動・native 保存。端末名と iOS を記録 |
| H | 文言・理解確認 | 日本語/英語の校閲、合成状態から保存対象と操作結果を説明できた記録 |
| A | 提出物照合 | 実 Archive、リソース、同一候補の画面、公開/同梱説明、Store 登録予定項目の一致 |

複数の記号がある項目は、それぞれの証拠を必要とする。M の成功だけで I を完了にしない。I/A の環境がない場合も、実装・M/B/H の準備は継続し、残る範囲を未実施として記録する。

状態は `未実施` / `実施中` / `不合格` / `機械確認済み・実機未実施` / `合格（証拠リンクあり）` / `非該当（理由・対象版あり）` を使う。表の初期状態はすべて未実施である。条件付き機能を採用しない場合は、項目の目的が不要な理由を記録して非該当とし、黙って削除しない。

### 共通の前提

1. 対象コミット・アプリ版・ビルドを固定し、日英の必須辞書を同梱した候補を使う。
2. 使用するのは合成メモ。実ユーザーの保存領域を容量充填・故障注入・初期化しない。
3. メモの題名、本文、ID、`createdAt`、`updatedAt`、しるし、`Note.locale`、復旧 raw の基準値を控える。表示だけの変更では、これらが変わらないことを必要な境界で比較する。
4. UI 言語、希望値、実効値、OS アプリ言語、端末言語/地域、読み返し方向を別に記録する。
5. 候補閲覧の成功、全文コピーの成功、保存の成功を別に判定する。0件の有効候補と候補不存在も区別する。
6. テスト専用の時間・保存先・native 応答の制御は、製品ビルドに混入させない。

## 7. 保存・復旧で必ず残す観測

### 最新版未保存と予備保存失敗

旧版Aを保存し、本文をBへ編集する。Aに対する遅い成功とBの失敗をそれぞれ返し、日英へ切り替える。どの版を説明しているかを、state・保存先・表示文の3つで比較する。本体B成功＋予備失敗の場合と、本体B失敗の場合の説明を分ける。文字列だけを期待値にするテストではなく、入力した版と保存先の内容を確かめる。

### 候補を見る・採用する・保存する

未保存のscreen、別のlocal、別のnative、0件の有効版を用意する。閲覧だけの前後で書込みがないことを観測し、採用操作では対象を再確認する。保存が失敗した場合は、候補を見たことをもって「復元済み」としない。保護枠の整理は利用者が選んだ候補だけで、通常削除のUndoと別の説明を持つ。

### その場の救済と再起動

保存待ち・保存失敗・競合待ちでBoundaryを発生させる。RAMに保持した全文をその場で読めてコピーできることを確認する。再読み込み後は確認済みの保存版を失わず、既存journal/nativeに残る未確定版を従来の復旧候補として扱うことも確認する。例えばA確定→Bのjournal/backup成功→primary失敗では、Aだけへ戻すためにBの候補を捨てない。**RAMだけにある未保存内容の再起動後の復元は保証しない。** 新たな永続下書きを追加する場合は別仕様・別試験として扱う。
