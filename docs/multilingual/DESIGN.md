## MLD-01 — 日英で一連の体験を完成させる

**採用仕様**

初めに公開するUI言語は `ja` と `en`。英語の正常画面だけ先に公開せず、保存失敗、競合、候補比較、削除、Undo、描画障害、原文コピー、アプリ情報、支援技術まで同じ完成範囲に含めます。

紙、墨、月、余白、穏やかな動きは両言語で共通です。「一行でも書きかけでも置ける」「自分の都合で戻れる」という体験を保ちます。操作の説明には具体的な語を使い、詩的な表現は短いブランド文へ置きます。英語の記録単位はnoteに揃えます。採用文はCOPY_AND_RELEASE.mdを正本とします。

書ける文字はUIのja/enに制限しません。英語UIで日本語の詩、日本語UIで英文、両UIでアラビア語を含む混在本文を扱います。本文の自動翻訳、自動言語判定、清書、要約は追加しません。

初版は無料・広告なし。AI、アカウント、同期、課金、分析、通知、Markdown、一般向け一括インポートなどを多言語化の一部として増やしません。

**将来**

zh-Hant、zh-Hans、ko、es等は、要望と継続的な校閲体制に合わせて1言語ずつ追加します。簡体字と繁体字を機械変換だけで完成扱いにしません。アラビア語本文の保持とアラビア語UI全体のRTL対応は、別の完了条件です。

## MLD-02 — 言語・文字方向・保存データを別の軸にする

| 軸 | 日英初版の責務 | 保存先・禁止する結び付け |
|---|---|---|
| UIの希望言語 | system / ja / en | メモとは独立した端末設定 |
| 実効UI言語 | 今の版で実際に表示できるja/en | 希望言語と別。systemを解決済みの値で上書きしない |
| 本人の文章の言語 | 初版は不明。本人による任意指定は将来 | UI言語・文字種・旧Note.localeから断定しない |
| 読書の向き | vertical / horizontal | 端末の共通表示設定。Noteへ書かない |
| 文章の左右方向 | 段落単位の自動方向処理 | 翻訳・文字順の変更とは別。表示のために制御文字を保存しない |
| 筆あと | 既存の4種の明示選択 | 既存のbrush設定を継承 |
| 書式 | 件数・日付の表示 | formatterの責務。保存・並び替えのキーにしない |
| タイムゾーン | 初版は表示時の端末の現在のもの | UI言語から国や時刻帯を推定しない |
| nativeのアプリ言語 | OSがこのアプリへ選んだ言語 | アプリ内overrideとは別 |
| ストア掲載言語 | 掲載文・画像・情報ページ | Web辞書・バイナリ宣言と別に確認 |

**メモの不変条件**

UI言語・読書方向・筆あとを変更するだけでは、題名、本文、id、createdAt、updatedAt、isFavorite、復旧候補、保護中のrawを変更しません。既存の「updatedAtは題名・本文・印を含むメモ全体の変更時刻」「固定状態が同じなら変更の新しい順」を継承します。

禁止するのは表示設定の変更を原因とする追加の加工・書込みです。切替前からの本人の編集に対する正当な自動保存、実行中の書込みの完了、対応する保存状態の更新は継続します。「言語変更中はメモの書込みが一切起きない」という試験条件にはしません。

`Note.locale` は既存保存形式の互換用フィールドとして扱います。現在のvalidatorは省略・ja・enを受理します。

- 既存の値は保持し、移行・削除・推測による補完をしません。
- **新規メモではNote.localeを省略することを推奨する採用案**とします。実装時の最新validator・書込み経路との整合を確認します。
- UiLocale型を保存用Locale型から流用しません。
- zh-Hant等をUIへ追加するために、Note.localeへその値を書き込みません。
- 未知のNote.localeがある保存データを、設定のfallback規則で修正して正常化しません。既存のデータ検査とraw保護を維持します。

## MLD-03 — 言語選択はアプリ情報内の一か所へ置く

「このアプリについて」に「言語 / Language」を置きます。選択肢は次の3つです。

| 保存する希望 | 表示 |
|---|---|
| system | システム設定に従う / System default |
| ja | 日本語 |
| en | English |

日本語・Englishはその言語自身の表記を使い、国旗を付けません。誤選択から戻れるよう、入口にLanguageを添えます。毎回の起動で言語選択を求めず、ホームの常設操作を増やしません。

既存のAboutScreenは背景のAppを保持した重ね表示です。この寿命を維持し、言語選択を理由に編集画面や復旧状態を作り直しません。選択後も同じ選択項目へフォーカスを保ち、閉じたら元の操作へ戻します。

**解決順**

1. 保存またはこの起動中に明示したja/enがあれば、その言語。
2. systemなら、iOSは公開APIで得るこのアプリのpreferredLocalizations、Webはnavigator.languagesの優先順。
3. native情報を取得できない場合だけ、Web側の候補を代替情報として使う。
4. 使える対応候補がなければen。

enへのfallbackは、英語の必須文言と救済・情報ページが完成した版で有効にします。現行の部分的なEn接尾辞だけを使って切替を公開しません。

候補を一つずつ検証し、不正なタグだけを飛ばします。ja-JPはja、en-US/en-GBはenへ照合します。例えば候補がfr-CA、ja-JP、en-USの順ならjaです。先頭が未対応というだけで残りを捨てません。将来の中国語照合はscriptと地域を扱い、単にハイフン前のzhへ縮めません。[S01]

アプリ内選択はWeb UIの希望です。iOS設定をプログラムで書き換える機能ではありません。アプリ内enとOSアプリ言語jaの組合せでは、nativeの編集メニュー等がjaになる場合を実機確認します。

## MLD-04 — 設定は既存の小さな保存方式へ寄せる

**採用する構成**

現行brushPreference.tsの「React外に現在値を保持し、libからlocalStorageを読み書きする」構成を基点に、端末表示設定の小さなadapterへ寄せます。コンポーネントが直接localStorageを操作しません。日英初版のためにCapacitor Preferencesや別の永続DBを追加しません。

| 設定 | キー | 値・扱い |
|---|---|---|
| UI希望言語 | zanshin.prefs.ui-language.v1 | system / ja / en |
| 共通の読書方向 | zanshin.prefs.reading-mode.v1 | vertical / horizontal。値が初期化済みの記録も兼ねる |
| 筆あと | zanshin.prefs.brush.v1 | 既存キー・既存値を継承 |

これはメモのprimary・backup・journal・native保存とは独立した設定領域です。設定変更でメモを再serializeしません。筆あとを新しいキーへ一括移行したり、同じ設定を二つのストアへ併記したりしません。

**失敗と競合**

- 選択はメモリ上で直ちに反映します。保存失敗時も、現在の起動中の選択を戻しません。
- 設定画面に「設定を保存できなかった」「次回は元に戻る場合がある」という意味を出します。本文の保存結果や保存済み表示を変更しません。
- 設定の失敗は編集を止める理由にしません。メモの保存側に独立した失敗がある場合は、その状態も保ちます。
- 初期読込みより後に利用者が選んだ値を、遅い読込み結果で戻しません。
- 非同期adapterを使う部分があれば、希望の世代と書込み順を管理します。en→jaの連続選択で、遅いenが永続設定の最後に残らない契約です。呼出し側の古い結果を無視するだけで、古い書込みの実行順問題を解決した扱いにしません。
- 同一オリジンの設定変更イベントを扱う場合、対象の設定キーだけを反映します。言語変更イベントをメモ再読込み・復旧probeへ流しません。

**旧版・未知の値**

将来の対応版が保存したzh-Hant等を日英版が読んだ場合、実効表示は対応範囲へfallbackしますが、元の希望値を自動でja/enへ書き換えません。不正・未知の値で起動を止めず、利用者が明示選択したときにその設定を保存し直します。未知の読書設定も勝手に消去せず、当該版では従来の縦書き表示を使います。

設定ストレージの破損を理由に、メモのraw・復旧候補を掃除しません。

## MLD-05 — Providerの寿命と保存処理の寿命を分離する

型付き同梱辞書と、安定したReact Contextで開始します。言語切替のためにライブラリの大規模導入、通信による辞書取得、アプリ再読み込みを必要にしません。

**起動**

明示済みのja/enは描画前に安全に読める範囲で解決します。systemでnative取得が必要な場合は、初期化を短い上限で打ち切れるようにし、失敗・無応答でもWeb側の候補とenへ進めます。初期化時間の具体値は実装時の比較値であり、本文入力を無期限に待たせる方式は不採用です。

native取得はI1で読み取り専用の小さなbridgeを用意し、I4で実ArchiveとOS設定を検証します。遅い結果はMLD-04の世代規則に従い、途中で選択したoverrideや変換中の入力へ割り込みません。

**切替で保持するもの**

| 範囲 | 保持する状態 |
|---|---|
| 編集 | 対象id、題名、本文、選択範囲、入力途中の状態、スクロール |
| 一覧・検索 | 検索語、結果、戻り先、カード位置とフォーカス |
| 保存 | 対象版、成功を確認した版、失敗reason、保護状態 |
| 復旧 | screen/local/native/保護候補の内容、選択中の候補、確認対象 |
| 削除 | 対象メモ、確定結果、Undoの期限と残り時間 |
| 表示設定 | 読書方向、筆あと、現在の設定保存の結果 |

App、NoteEditor、入力要素、復旧画面のkeyにlocaleや訳文を使いません。localeでrootを作り直さず、同じツリーの文言とhtml.langを更新します。[S02]

辞書やt関数の参照が変わっただけで、自動保存、候補比較、復旧probe、本文再読込み、Undoタイマーを再起動しません。副作用は元のデータ版・状態コード・期限に従います。

IME変換中の外部言語変更は、**希望値だけ先に受け取り、UIへの反映は変換確定後まで待つ**方針にします。入力要素の差替えで解決しません。composition handlerの有無だけで現行を不具合と判定せず、実際の入力・確定・保存版で検証します。

**OS設定へ移る経路**

アプリ内で辞書を変える操作と、OS設定でアプリ言語を変える操作を分けます。OS設定への案内を製品へ追加する場合は、移動前に現在版の本体保存を確認し、失敗・競合時は原文の取り出しと移動中止を選べるようにします。OSから直接変更したときのプロセス再起動を、RAMだけの保護で乗り越えられるとは説明しません。

## MLD-06 — メッセージは意味と引数を型で揃える

日本語・英語辞書は同じMessages型を満たします。既存の `Copy = typeof copy` の日本語リテラル型を、そのまま英語辞書の型に流用しません。En接尾辞のある値を集めただけで翻訳完成としません。

- キーは表示の意味を表します。訳文や配列上の位置をIDにしません。
- 文全体、対象、隣の操作を翻訳単位にします。「数＋名詞＋助詞」の断片結合を各画面へ散らしません。
- noteCount、versionCount、candidateIndex、seconds等の引数を区別します。
- 題名、本文、日時は差し込み値です。本人の文字列を翻訳辞書やHTMLとして解釈しません。
- ブランドの行配列は言語ごとに設計し、日本語の改行位置を英語へ強制しません。
- 同じ操作にはCOPY_AND_RELEASE.mdの同じ名称を使います。日本語の「メモを書く」、英語のNew noteを入口ごとに別名へしません。
- 日英辞書、最小救済辞書、必要な書式は同梱し、オフラインで使えます。

**処理と表示の分離**

保存・復旧層は状態コード、対象版、確認できた事実を返します。表示側が現在の辞書へ写像します。getSaveFailureMessage等を整理するときも、翻訳済み文字列を状態識別子にしません。

復旧候補はsource/slot等の安定した意味を保持し、候補を開いた時点の訳済みlabelだけを状態へ固定しません。言語変更時は同じ候補のラベルを描き直し、翻訳のためにストレージを読み直したり候補を取り直したりしません。

追加言語で複数形・文法・翻訳運用が複雑になった時に既存i18nライブラリを再評価します。日英初版で独自の複雑なメッセージ構文を作りません。

## MLD-07 — 保存・復旧・救済の意味を両言語で同じにする

| 確認できた状態 | 表示する意味 | 表示してはいけない意味 |
|---|---|---|
| 現在版の本体書込みが失敗 | 最新の変更が未保存、理由と取り出す経路 | 過去の成功を現在の「保存済み」として出す |
| 本体は現在版、予備保存だけ失敗 | 現在版は保存済み、端末内の復旧用コピーは更新できなかった | クラウド同期や機種変更後の復元まで保証する |
| 本体の読込み・検査が失敗 | 安全に確認できない、上書きを止めている | メモが存在しない、0件と確定した |
| 有効な保存版に含まれるメモが0件 | この保存版にはメモがない | 全件削除の履歴を確認した |
| 候補を表示・選択した | 別の版を見ている、比較している | 本体への保存が完了した |
| 原文コピーに成功した | 原文をクリップボードへ渡した | メモをアプリへ保存した |
| 削除の保存が失敗した | 削除は保存先へ確定していない | 削除済みだけを表示する |
| 保護枠が満杯 | 確認・取り出し・明示的な整理が必要 | 自動で古い候補を削除する |

本体の確定版は、本体書込み成功を確認した内容、または現存する本体との一致を確認して明示採用した版です。native候補の選択だけでは本体保存済みにしません。

0件の候補から、なぜ空なのかは分かりません。現在のrecoveryReviewEmpty、nativeRecoveryAlternativeNotice(0)等にある「すべて削除済み」という断定は、観測できる「この版にはメモがない」へ揃えてから訳します。1つの版に3件のメモがある状態を「3つの復旧版」と呼びません。

「見る」「採用する」「保存する」「コピーする」を区別します。採用と書込みが1つの操作でも、結果は実際の書込みに従います。候補を整理した後に別の書込みが失敗した場合は、全体を「何も変更していません」と説明しません。

削除は既存の直前1件・10秒・現在の起動中という契約を継承します。言語切替でUndo期限を延長、短縮、再生成しません。

**例外画面**

AppErrorBoundaryは通常のI18nProviderの障害も捕捉できる外側に置きます。最後に安全に解決できたja/enと、Providerや複雑なformatterに依存しない最小同梱辞書で救済を表示します。解決結果も得られない場合はenを使います。

CopyTextButton等の救済経路を通常Provider必須にすると、Boundaryだけ独立しても救済が壊れます。救済の説明、ボタン、成功・失敗、手動選択の表示まで独立して使える構成にします。

W1のdraftRescueは**同じプロセス内のRAM保護**です。通常ProviderやAppの描画が壊れても、保持できた原文へ届くことを継承します。プロセス再起動、再読み込み、アンインストールを越える未保存版の永続復元ではありません。救済時に強制保存、競合判定の迂回、raw初期化をしません。

## MLD-08 — 横書き読書を加え、初期化は一度だけ行う

日英公開では横書きで長文を読めることを必須にします。現在の縦書きの文書構造、操作・日付を分離した配置は継承します。編集は引き続き横書きです。

**日英初版では共通の読書方向を1つだけ持ちます。** メモごとの方向マップや複数階層の設定画面を新設しません。将来メモごとの選択が必要になった場合は、Noteと別の端末設定へ追加し、メモ別の明示選択を共通設定より優先する設計にできます。

| 初期化条件 | 採用する方向 |
|---|---|
| すでに有効な読書設定がある | その値を維持 |
| 旧版利用の証拠がある | vertical |
| 新旧を判断できない・保存先が未確認・設定読込みが失敗 | vertical。新規と決めつけない |
| 検証済みの起動結果から新規導入と判定できる | 初回の実効UIがjaならvertical、enならhorizontal |

新規判定にメモ件数0だけを使いません。既存の有効な空保存版、journal、復旧候補、過去の設定などは旧利用の証拠になり得ます。既存の保存・native確認結果を再利用し、言語設定用に別の破壊的probeや保存データ走査を追加しません。判定できない場合は従来表示を保つ方針に固定します。

読書方向の設定値を、初期値を決定した独立の記録として保存します。以後、UI言語を変えても再初期化しません。初期設定の保存に失敗した場合も、その起動中に言語変更を理由として方向を変えません。

読み返しに「縦書き / 横書き」の控えめな選択を置きます。どちらが選ばれているかは見た目と支援技術へ伝えます。設定の保存失敗は本文保存と別に扱います。

- UI言語だけの変更：読書方向、選択、スクロール位置を保つ。
- 利用者が方向を変えた場合：可能な範囲で同じ段落付近を表示する。横のピクセル値をそのまま縦へ流用しない。
- 縦書き：実際に続きがある時だけ、左へ読む意味の案内を出す。
- 横書き：縦書き専用の案内を出さず、下へ末尾まで進める。
- 題名・本文の種類やNote.localeを見て自動で方向を切り替えない。

<a id="mld-09"></a>

## MLD-09 — 段落の方向と、原文を選べる描画を一緒に成立させる

**採用する表示契約**

本文は論理的な段落ごとに方向を扱います。全文の最初の強い文字だけで後続の全段落を同じ基底方向へ固定しません。左右方向は自然言語の推定と別です。

- 明示改行と、画面幅による自動折返しを区別する。
- 日本語・英語・アラビア語・URL・数字・括弧を混ぜても、保存文字順を並べ替えない。
- URLやLatin文字から始まるアラビア語段落は、自動判定ではLTRになり得る。多数決による独自言語判定で補正しない。
- 数字だけの行・空行の配置とキャレットは、文字順と分けて確認する。
- アプリが用意した題名ラベル、日時、操作文まで本文の方向へ巻き込まない。
- 方向制御文字を表示の都合で原文へ挿入しない。本人が入力した制御文字は一括削除しない。

**比較して確定するDOM**

優先候補は、読み取り本文を `pre dir="auto"`、編集本文を `textarea dir="auto"` で扱う構造です。HTMLの既定描画では両者にunicode-bidi: plaintextが使われ、通常の単一pへdir=autoを追加する場合と異なります。[S03]

現行はLFごとのspanと空行U+200Bによる見た目を持っています。優先候補へ機械的に置き換えるだけで完了にせず、次の2候補を同じ本文・同じ筆あとで比較します。

| 候補 | 保つもの | 確認する弱点 |
|---|---|---|
| A：原文を一つのテキストとしてpreに渡す | 書体、紙面、原文のLF・字下げ・空行。preの既定等幅書体・余白は上書き | 行装飾の再現範囲、縦横の段落方向、先頭末尾LF、選択コピー |
| B：行・段落の要素を残して改善する | 現行の行ごとの表情と方向の制御 | 余分な改行や装飾文字を選択へ混ぜない。語・書記素の字形形成を分断しない |

Aが受入を満たせば採用します。満たさない点がある場合だけBを検討し、選択理由と差分をACCEPTANCE.mdへ残します。見た目が変わる理由を示さず既存の筆あとを廃止せず、逆に装飾の維持だけを理由に原文の選択を壊しません。

原文にないU+200B等を、選択・コピーされる文字列へ混ぜないことが目標です。必要な空行の高さは、原文または選択文字列を増やさない構造で表します。明示コピーとOSの範囲選択コピーは別に検証します。

**縦書きの混在**

text-orientation: mixedを比較の出発点にします。Arabic等が下から上へ流れることを、文字列反転の不具合と即断しません。全体をuprightにすると横方向の連結文字が孤立形になる仕様があるため、読みやすさの一律修正に使いません。[S04]

縦書きでは、英字の単語をまとまりのまま `text-orientation: upright` で正立させます。UI 言語に関わらず同じ組版を適用します。URL と、アラビア語など連結が必要な文字は `mixed` を使います。英字の結合アクセントと接続記号を同じ要素に保ち、原文に改行・空白を挿入しません。横書きと共通の DOM を使い、表示の向きだけを切り替えます。

Latin文字や数字の全角化は行いません。原文、字形形成、選択、横書きへの選択を成功条件にします。

<a id="mld-10"></a>

## MLD-10 — 筆あとを継承し、UI言語だけで本人の字を変えない

既存のmincho / fude / boku / tegakiと同梱フォントを継承します。言語変更でdata-brushや保存された筆あとを変更しません。筆あと選択のラベル・説明・サンプルの言語範囲も翻訳対象です。日本語の固定サンプルを残す場合は、その箇所が日本語であることを明示します。

英語UIだから日本語本文まで欧文向けの書体へ切り替えるセレクタは使いません。書体設定、読み方向、本人の文章の言語は別に保ちます。

言語不明の漢字だけの文章では、日本語・簡体字・繁体字の正しい地域字形を一意に決める情報がありません。書体を選ぶために言語を推測してNoteへ書き込みません。将来、本人による任意の表示指定を検討できます。

フォールバックは文字体系と結合文字のまとまりを保つ必要があります。フォント名を並べたことだけで、全字形の収録や端末間の同一描画を保証しません。[S05]

**比較の基点。実測済みの完成値ではない**

| 要素 | 基点・候補 |
|---|---|
| 本文入力 | 現行18px。選んだ筆あとを維持し、縮小を最初の対策にしない |
| 操作・状態説明 | system sansを中心に、通常14〜16pxを比較 |
| 英文・混在本文の横書き | 18px前後、line-height 1.7〜1.9、letter-spacing: normalを比較 |
| 日本語中心の縦書き | 現行の紙面を基点に、列間・字間を混在fixtureでも比較 |
| 小さな補助情報 | 12〜13pxを比較し、文字拡大と背景上のコントラストを確認 |
| 操作領域 | 44×44 CSS pxを設計目標とし、配置を実機で確認 |

アラビア語等へ日本語用の広い字間を一律継承しません。筆記的に連結する文字へのletter-spacingには互換性上の注意があるため、通常の字間から比較します。[S06]

長い訳文は折返し・高さの伸長・操作の縦積みで受けます。本文、戻る、削除確認、保存エラー、候補比較、アプリ情報を固定高へ押し込みません。375×667、390×844、430px幅、200%相当で内容と操作へ到達できることを確認します。

紙のコントラスト、focus、Reduce Motion、装飾と固定操作の分離は既存の改善を継承します。文字量を揃えるために説明を省略したり、警告を読めない短時間だけ表示したりしません。

<a id="mld-11"></a>

## MLD-11 — UIの操作名と本人の文章に別の言語範囲を与える

html.langは実効UI言語に追従します。ja/enのUI方向はLTRです。ブランドとして残す「残心」や固定の日本語サンプルは、必要な箇所へjaを明示します。

本人の題名・本文は旧Note.localeから判定しません。日英初版では自動言語判定を追加せず、未知の内容は `lang=""` を比較の基点とします。空のlangは「明示的に不明」であり、自動で適切な声を選ぶ保証ではありません。[S07]

**入力欄の構造**

value、placeholder、aria-labelを同じ要素に載せたままlangだけ変更すると、UI説明も本人の本文と同じ言語範囲になります。自然言語の属性値と内容の言語が異なる場合の境界を整理します。[S08]

- 入力の目的はUI言語の独立したlabelへ置き、入力要素と関連付ける。
- 補足もUI言語の説明要素へ置く。
- 本人の値を持つtextareaは内容側の言語範囲として扱う。
- 初版はUIの空欄案内を別要素へ移す方針とし、未知言語のtextareaに置いたplaceholderだけを唯一の説明にしない。
- 「本文がありません」、無題のfallback、日付、操作文は本人の文章と別のUI範囲にする。

ラベルの可視・読み上げ専用の使い分けは紙面に合わせます。目的が不明になる配置にはせず、通常のフォーカス順を余分な言語断片で増やしません。

**カードと通知**

現行カードの本人由来見出し、作成日、固定状態という識別情報を継承し、現在の日本語文字列連結を文全体の翻訳または構造化した名前へ移します。題名をUIの文へ差し込む場合は適切な方向隔離を使い、日時や隣の操作の括弧・数字に影響させません。

見える操作名はアクセシブルな名前へ含めます。New noteと見えるのに、音声操作では別の詩的名称を要求しません。[S09]

aria-labelledby等の構造を整えたことだけで、VoiceOverの混在言語読み分けを合格にしません。DOM上の指定と、実際の発音・読み順・操作性を別に記録します。

保存状態の読み上げは意味のある状態変化に絞り、UI言語を変えたことで全カードや同じエラーを大量に読み上げ直しません。失敗・競合・保存停止の重要性は保ちます。

<a id="mld-12"></a>

## MLD-12 — 入力を途中で切らず、受け取った原文の境界を明確にする

**題名の200**

200は見た目の一文字のまとまり、すなわち書記素数の目安です。日英初版では厳密な保存上限にしません。maxLength=200をそのまま「200文字」の仕様として残さず、超過入力や貼付けを黙って切りません。

題名欄は現行の高さ可変textareaを継承します。長い題名を開く、戻る、言語を変えるだけで切断・不正化しません。200付近で常時強い警告やカウンターを増やす必要はなく、案内を出す場合も入力・保存を妨げない補助情報に留めます。

Intl.Segmenterが使えない場合に不正確な「文字数」を上限判定へ使いません。正しい計数を提供できないときは、文字数の案内を省けます。保存容量・性能の上限は、題名200の目安と別に設計します。

**題名の改行**

現行は意味上の一行の名前を、見た目は折り返して編集する設計です。変換中以外のEnterで本文へ移る挙動を継承します。isComposing等の既存の変換確定保護を取り除きません。

現行handleTitleは、実際の題名編集で受け取ったLFを半角空白として扱います。この方針を日英初版でも明示的な入力契約として継承します。保存済み題名に改行がある場合、開くだけ・本文だけの編集・UI変更でこの処理を実行しません。貼付け後に受理する題名と、保持している既存原文を区別し、コピーはモデルから行います。

**本文・IME・入力支援**

handleTitle/handleBodyが入力欄の全文を受け取る形を維持します。キーの一文字ずつをアプリが組み立てる方式へ変えません。

- 変換途中でtrim、NFC/NFKC、slice、句読点置換、翻訳を行わない。
- 日本語のかな変換、韓国語の組立て、拼音、音声入力、選択置換、貼付けを同じ編集経路で受ける。
- UI言語を理由にキーボードを強制切替しない。
- 本文・題名はOSの入力支援を尊重し、検索と同じ抑制設定を機械的に適用しない。
- composition handler不足という理由だけで不具合と断定せず、確定後の全文・選択範囲・保存対象版で判断する。

**原文保持の範囲**

| 操作 | 契約 |
|---|---|
| 保存済み文章を開く・読む・言語を変える | 保存済みの文字列を書き換えない |
| 本文を実際に編集する | textareaが受け取った全文を保存する。改行はDOMのLF化を編集境界として扱う |
| 題名を実際に編集する | 上記の題名入力契約に従う。旧題名を先回りして整形しない |
| 明示コピー・救済 | 保持している題名・本文・下書きを入力元にする |
| 検索・表示用短縮 | 比較用・表示用の値だけを作り、保存へ戻さない |

textareaのAPI valueは改行を正規化します。[S10] 外部アプリから貼り付ける前のバイト列を、すべてのOSで同一に保存する保証ではありません。現在の受理済み文字列と既存の保存原文を基準にします。

例外画面・復旧画面に単一行inputが残る場合も、その表示valueを救済原文の正本にしません。題名の全文が確認・選択できることを、現在の編集textareaと合わせて確認します。

<a id="mld-13"></a>

## MLD-13 — 検索は共通の比較規則を使い、原文位置を取り違えない

対象は題名と本文です。日付印、朝・昼・夕・夜、固定ラベルは検索対象に追加しません。「題名と本文から探す」という意味を補助説明にできます。

**採用する比較規則**

題名・本文・検索語へ共通に、比較用の値だけ次の順で変換します。

1. NFC正規化。
2. タブとUnicode General_Category=Zsの連続を、半角空白1個へ揃える。
3. UI言語に依存しないUnicode小文字化。
4. 検索語の外側の空白は既存方針どおりtrimする。

CR、LF、U+2028、U+2029を半角空白へ変えません。blue＋LF＋moonをblue moonで一致させず、改行・段落を跨いだ一致を新設しません。検索語の中間に改行が残る場合も、別行の語を1行の語句として結び付けません。

NFCは正準等価な表現を比較するための処理です。NFKC、アクセント除去、全角半角の同一視、読み仮名、翻字、翻訳検索は追加しません。ßとss、Iとıなどの高度な言語別等価性も今回の単純小文字化と混同しません。[S11]

見えない文字をすべて削除する処理は使いません。NBSPの非改行性、詩の字下げ、ZWJ/ZWNJ等は原文表示・保存・コピーで維持します。

**検索欄の入力支援**

autoComplete=off、spellCheck=falseに加え、autoCorrect=off、autoCapitalize=noneを明示する方針を採用します。これでOSの全入力方式が必ず同じ動作になるとは説明せず、固有名詞・造語・小文字から始まる語を実機確認します。[S12]

**一致箇所と現行noteDisplay**

現在のmatchesNoteとmatchExcerptで別の比較規則を持たせたままにしません。NFCや空白の等価化によって比較文字列の長さが変わるため、比較用indexをそのまま原文のindexとして使いません。

日英初版の推奨は、**一致した元の行を示し、CSSによる省略を使う**方法です。現在の「検索で見つかった理由が分かる」という改善を維持し、精密な部分強調は必須にしません。見える範囲に一致語を出すために周辺だけ切り出す場合は、原文との範囲対応と元段落の方向を持ちます。正規化に失敗した位置から別の文章を提示しません。

抜粋の先頭がURLやArabicになったことで、元段落と違う方向に再判定される条件を確認します。題名・抜粋・日時・操作文は別の方向範囲で扱います。

**強調は条件付き**

初版に強調を追加する場合だけ、原文位置と書記素境界を管理します。Arabic語中の一致断片を個々のbdiで隔離せず、別フォント・余白・字間・方向指定を部分境界へ持ち込みません。字形形成を分断する境界はCSSでも規定されています。[S06]

<a id="mld-14"></a>

## MLD-14 — 無題の識別と保存値の空判定を分ける

現行の本文由来のカード見出しを継承します。見出しが題名から来たか、本文の表示用抜粋か、UIの無題fallbackかを、訳文の一致比較ではなく意味として扱います。

| 内容 | 表示の方針 |
|---|---|
| 識別できる題名がある | 本人の題名。カードでは省略できるが全文経路を残す |
| 題名がなく本文がある | 本文の最初の識別できる行を表示用見出しにする。titleへ保存しない |
| 題名が不可視文字だけ | 保存値を残し、識別できる本文・日付等へ代替する |
| 題名・本文から識別できない | UIの無題表示と日付・固定状態などで識別を補う |

表示上の空と、保存データが空であることを同じ判定にしません。ZWSP、WORD JOINER、ZWJ等だけの見出しでカードを見失わないようにしますが、これらを原文から一括削除しません。操作して書いた下書きを、表示上見えないという理由で自動削除しません。

検索欄が見えない文字だけでも、検索を解除する操作へ到達できるようにします。

短縮・計数は書記素のまとまりを守ります。家族絵文字、肌色、旗、結合アクセント、濁点、variation selectorを例にします。[S13]

現行のIntl.Segmenter不在時のArray.fromは、完全な書記素分割の代替ではありません。**日英初版は、完全に分割できない環境ではJSで短縮せず原文をCSSで省略する**方針を採用します。利用可能なAPIだけを理由に最小OSを引き上げません。必要な全文は読書・編集・救済から到達できます。

<a id="mld-15"></a>

## MLD-15 — 件数と日時は表示に限定し、地域や時刻帯を推測しない

**件数**

一覧、検索結果、復旧版の件数を別の文として辞書へ置きます。Intl.NumberFormatと必要な複数形処理を使い、画面側で英語のsを足しません。[S14]

0、1、2、11、1000等で確認します。一覧0件、検索一致0件、有効な復旧版の0件は異なる意味です。noteCountとversionCountを同じ引数へしません。

**日付印と詳細**

| 表示 | 日英初版の採用 |
|---|---|
| ブランドの日付印 | 現行のYYYY.MM.DD、グレゴリオ暦、0123456789を維持 |
| 日付印の意味 | createdAtの「作成日」。updatedAtと入れ替えない |
| 変更日 | 題名・本文・印を含む変更時刻。本文編集だけの時刻と呼ばない |
| 詳細日時・aria | formatterの引数として実効UIのja/enを使い、意味を明示する |
| 時間帯 | morning / afternoon / evening / night等の意味と訳を分離 |
| 不明・不正な日時 | 推測で「夜」「最新版」「今日」等を埋めない |

時間帯の境界は現行の5〜10時、11〜15時、16〜18時、19〜4時を維持します。UI言語を変えただけで区分を変えません。

**初版の地域方針を限定する**

共通en辞書を使い、en-US/en-GB辞書や地域選択UIは作りません。詳細日時のformatLocaleは実効ja/enから渡す共通書式とし、グレゴリオ暦・Latin数字を明示します。これはOSの地域別の日付順・暦・数字設定を完全再現する契約ではありません。

formatLocale、calendar、numberingSystem、timeZoneは独立した入力として設計します。将来OSの地域情報を採用する場合も、UIのenを米国という国や米国のタイムゾーンへ置き換えません。Nodeでのen-US、en-GB、和暦、仏暦等の参考例は、現在の製品の表示結果や対応済み地域を意味しません。

表示時のタイムゾーンは初版では端末の現在のものを使います。UI切替では保存済みISO日時を変更しません。時刻帯変更後の見え方が変わり得ることと、保存された瞬間が変わることを区別します。表示文字列をソート・復旧比較のキーにしません。

R37の作成時タイムゾーン保持は将来仕様のままです。過去の作成国や時刻帯を推測で補完する自動移行はしません。保存版の記録日時、メモの変更日時、作成日を混同せず、0件の候補に存在しない日時を作りません。

<a id="mld-16"></a>

## MLD-16 — アプリ・native・情報ページ・ストアを同じ対応範囲へ揃える

nativeでsystemを解決するため、Bundle.main.preferredLocalizationsを読み取り専用bridgeで取得します。位置情報・IPアドレス・端末識別子は不要です。公開APIを使い、OS設定を書き換えません。[S15]

日英の公開条件を満たしたリリースで、Webの完成言語集合、CFBundleLocalizations、knownRegionsをja/enへ揃えます。未対応言語のアプリ側fallbackをenとする方針に合わせ、developmentRegion / CFBundleDevelopmentRegionのenへの変更は、完成版のArchiveで検証します。現在jaである値を、辞書が途中の段階で先に変えません。

最低OSはリポジトリの実設定と実際に提出するArchiveを確認します。現在の設定値を根拠に、すべてのIntl APIやWKWebView挙動が使えると仮定しません。対応OS変更は別の判断として扱います。

プライバシー・サポート・保存の注意は、アプリ内でオフラインでも読める日英の内容を用意します。公開ページにも同じ意味の各言語を用意し、相互の入口を残します。公開URLは実際に管理・公開したものだけを案内します。

支援先は現在のGitHub Issuesという性質に合わせ、投稿が公開されること、本文や個人情報を必須にしないことを伝えます。問い合わせでは版、UI言語、操作、表示メッセージを任意で添えられるようにします。英語ページの存在を、返信言語や返信速度の保証へ広げません。

アプリ内名、ホーム画面名、ストア掲載名は別の管理対象です。英語の実UI画像、掲載文、情報ページ、審査向けの操作説明を同じ提出版へ揃えます。ストアの主言語とアプリ内fallbackは別に扱います。Web辞書追加とApp Store Connectのローカライズ追加は互いを自動で完了させません。[S16]

<a id="mld-17"></a>

## MLD-17 — 翻訳の存在と公開可能な完成状態を分ける

辞書の型で必須キーと引数を揃え、COPY_AND_RELEASE.mdの台帳で文脈・意味・確認状態を管理します。外部の翻訳管理サービスは初版の必須条件にしません。

原文、訳文、引数、表示条件、操作結果の意味が変わったら、同じキーに訳文があっても要再確認へ戻します。fingerprintは確認対象の追跡に使えますが、実装の意味変更を自動で完全検出するものではありません。実装者が意味の注記も更新します。

| 段階 | 確認すること |
|---|---|
| 開発・CI | 必須キー、空訳、引数、未確認・要再確認の残り |
| 文言確認 | 保存・破棄・候補・件数・取り消し等の意味 |
| 実画面確認 | 長い訳、差し込み値、200%、aria、フォーカス |
| 公開判定 | 実装コミット、提出版、native宣言、画像・情報ページとの一致 |

未完成の言語は選択肢や対応宣言へ出しません。すでに公開した言語に更新漏れがある場合は、新しいビルドの公開を止めて揃えます。自動で言語を選択肢から消し、既存利用者を別言語へ戻す運用にはしません。

runtime fallbackは想定外の障害への救済です。fallbackが出ることを翻訳完了の証拠にしません。特に保存・破棄の説明は、対象・主文・ボタンの一式を同じ理解可能な言語で示します。通常辞書が使えない場合は、MLD-07の確認済み最小救済表示へ退避します。

疑似翻訳は開発限定です。JavaScript辞書を長くしたり、境界の分かる表記にしたりして欠け・未抽出を見つけます。Xcodeの疑似言語だけで独自JS辞書も変換されたと判断しません。

## MLD-18 — 実機で決める項目と実装時の出口

以下は未確認を残したまま「対応済み」としないための決定表です。詳細ケースと記録はACCEPTANCE.mdを正本とします。

| 比較・確認 | 固定する契約 | 記録して決めること |
|---|---|---|
| preと現行行要素 | 原文、段落方向、選択、書記素を保つ | DOM方式、行装飾の再現、先頭末尾LF、OS選択コピー |
| 横書き・縦書き | 利用者の選択を保ち、全文へ到達できる | 各方向のスクロール主体、同じ段落への復帰 |
| 4種の筆あと | 選択はUI言語から独立 | Arabic連結、結合記号、fallback、通常・拡大の可読性 |
| labelと本人のlang | UI説明と未知内容を分ける | VoiceOverの名前・声・読み順、音声操作 |
| IME・音声・貼付け | 原文を途中切断しない | 実イベント順、確定後の全文、言語変更保留の反映 |
| 設定bootstrap | 無応答で起動不能にせず、遅い結果で選択を戻さない | 待機上限、native失敗時の結果 |
| OS経由の言語変更 | 保存状態とRAM救済の保証範囲を守る | 再起動、アプリ別言語、nativeメニュー |
| 公開 | 同じ版の日英完成を確認 | 母語話者校閲、最低OS・現行OS、実Archiveと掲載 |

既存W1〜W5の合格範囲は引き継ぎます。多言語の都合でprimary/backup/journalの仕様、候補の保護、復旧の採否を再設計しません。

実装開始時は最新mainとの差分を確認し、横書き・設定・辞書等が既に増えていたら、その実装を評価して統合します。本書のファイル名や構成を理由に同じ責務を重複作成しません。

合成fixtureは検査用の入力と期待条件です。Note配列の保存形式へ直接インポートせず、ui_locales_to_checkをNote.localeへ写しません。外国語例文を製品コピーの校閲済み訳として扱いません。
