# 多言語版のコピー、翻訳更新、公開条件

更新日: 2026-11-27  
実装照合の基準: `4ec10d1`（PR #51 のストア改善統合後）  
状態: 採用仕様と公開条件。候補版の [文言台帳](translation-ledger.json) と [実施結果](ACCEPTANCE.md) を参照してください。

この文書は、[初回調査](audits/round-1.md)と[第2回調査](audits/round-2.md)を現在のコードへ適用する方針を定める。調査当時の基準は `6b40f44` であり、当時の未実装項目や画面部品の記述を現在の不具合として引用しない。多言語の受入条件は [ACCEPTANCE.md](ACCEPTANCE.md) に集約する。

## 1. 初版で完成させる範囲

初めて公開する多言語版は **日本語 `ja` と共通英語 `en`** を一組として完成させる。日英それぞれについて、一覧・入力・読み返しだけでなく、保存失敗、競合、候補比較、削除、全文取り出し、描画例外、このアプリについて、同梱プライバシー・サポート説明までを対象にする。

今回の範囲は UI と表示方法の改善である。本人のメモを翻訳する機能、AI、アカウント、同期、追加データベース、タグ、課金、広告を追加しない。現在無効の広告・Premium 画面は初版の到達可能範囲に含めず、それらの訳の有無を公開必須辞書の分母へ混ぜない。機能を有効にする将来の版では別途対象へ加える。

以下は独立した値として扱う。

| 値 | 意味 | 今回の扱い |
|---|---|---|
| UI の希望言語 | `system` / `ja` / `en` という利用者の選択 | メモとは別の設定として保存する |
| 実効 UI 言語 | 今の画面で使う、完成済みの辞書 | 希望を解決した `ja` または `en` |
| `Note.locale` | 保存メモが持つ既存の属性 | UI 言語で上書き・一括移行しない |
| 読み返し方向 | 縦書き / 横書き | アプリ共通の独立設定。UI 言語変更に追従させない |
| `lang` / `dir` | 文言の言語 / 文字の左右方向 | 本文と UI ラベルを分け、段落と操作単位に適用する |
| 日付表示の locale・暦・数字 | 表示書式 | 保存した時刻・並び順・メモの内容とは分ける |
| タイムゾーン | 日付を表示する際の時差 | UI 言語から作成地を推測しない。R37 の schema 変更は保留を維持 |

### 最新コードとの接続

| 現在の実装で確認したこと | 多言語版で必要な追加 |
|---|---|
| `src/lib/i18n.ts` は日本語を主とし、一部に `...En` の補助表現がある | キーと引数を揃えた独立の日英辞書へ移す。既存の英語補助表現を、完成した英語 UI と数えない |
| 日本語の作成・先頭固定・削除説明が更新され、英語側には `Place new words`、`treasured trace`、`a short while` 等が残る | 操作の変更を日本語・英語・補助説明へ同時に反映し、古い訳を要再確認にする |
| `nativeRecoveryAlternativeNotice(0)` と `recoveryReviewEmpty` は、0件を削除済みと断定する | 両方を「この保存版にはメモがありません」の意味へ直す。数だけから削除履歴を作らない |
| 題名は `textarea` になり、`maxLength={200}` は残る | UTF-16 の強制制限を、書記素による200の目安へ見直す。旧単一行 `input` の改行除去を現在の不具合にしない |
| `noteDisplay.ts` に `Intl.Segmenter` の存在確認がある。代替は `Array.from` | サロゲートを分断しないことと、結合文字・ZWJ 等を分断しないことを区別する。最低対応 OS で安全な表示境界を設計する |
| `draftRescue.ts` は React の表示範囲の外に最新下書きを保持する | **RAM 上の救済であり、再読み込み・終了・再起動後の永続化ではない。** 言語変更のためにリロードしない |
| native の `CFBundleDevelopmentRegion` / `developmentRegion` は `ja`、宣言言語も `ja` | 日英が完成した版で初めて `ja` / `en` 宣言と `en` fallback へ揃える |

## 2. ブランド文と操作名

残心の雰囲気は、短い導入文、余白、紙や筆の表現に置く。操作名・保存状態・取り消し範囲は、何が起きるかを具体的に書く。`trace`、`release`、`place words` を全操作へ一律に広げない。

「残心 / Zanshin」はブランドとして扱う。日本語のアプリ内説明をそのまま唯一の辞書的定義として `Zanshin means ...` と断定せず、このアプリが大切にしている意味として説明する。

以下の英語は **実装に渡す文案であり、英語校閲・実画面確認は未実施**。日本語側も意味の修正対象を含む。用語を揃えたことと、製品コピーとして承認されたことは別に記録する。

| 用途 | 日本語の基準 | 英語案 | 適用条件 |
|---|---|---|---|
| 新規作成 | メモを書く | New note | 新しいメモの入力を始める |
| 題名 | タイトル（任意） | Title (optional) | 題名を必須にしない |
| 編集 | 編集する | Edit | 表示中のメモを編集する |
| 一覧へ戻る | 一覧へ | Back to notes | 実際の戻り先が一覧の場合 |
| 検索へ戻る | 検索結果へ | Back to search results | 保持した検索状態へ戻る場合 |
| 読書へ戻る | 読み返しへ | Back to reading | 実際の戻り先が読書の場合 |
| 読み返し | 読み返す | Read | 表示方法を変える操作。保存成功の意味を持たせない |
| 先頭固定 | 先頭に留める | Pin to top | 先頭のグループへ置く。しるしの付け外しも `updatedAt` を更新する |
| 固定解除 | 先頭固定を解除 | Unpin | 同じ状態の逆操作 |
| 検索対象 | 題名と本文から探す | Search titles and text | 日付・時刻・意味検索は含めない |
| 通常の削除 | このメモを削除 | Delete this note | 対象が特定された削除。説明に直前1件・10秒・再起動不可を含める |
| 取り消し | 元に戻す | Undo | 通常の削除に対する、現在有効な取り消しだけ |
| 保存再試行 | もう一度保存する | Try saving again | 最新版の本体保存を再試行する |
| 予備保存の再試行 | 予備保存をもう一度作る | Retry recovery copy | 本体保存失敗と区別する |
| 候補を表示 | 内容を確認する | View contents | 閲覧だけでは採用・保存しない |
| 原文の取り出し | 本文をコピー / タイトルをコピー | Copy text / Copy title | 保持した全文を渡す。短い一覧抜粋をコピーしない |
| 言語設定 | 言語 / システム設定に従う | Language / Follow system settings | `system` という希望値を保持する |

空の画面の補足案は `A line is enough.`、ブランド説明案は `Write a little. Return whenever you like.` とする。追加するかは実画面の密度と重複を見て決め、機械的にすべて表示しない。固定コピーの自然な改行は翻訳ごとに設計できるが、本人のメモの改行をその対象にしない。

## 3. 保存・復旧・削除の意味を先に固定する

コピーは、内部の理由コードと対象の編集版に基づいて表示する。表示済みの日本語文字列を state に保持して翻訳し直す方式にしない。言語変更で失敗の理由、候補、再試行、選択中の版、Undo の締切を作り直さない。

| 状態・操作 | 説明する事実 | 日英の文案例 / 誤って含めない意味 |
|---|---|---|
| 最新版の本体保存成功 | 表示対象の最新版の書込みが確認できた | 保存済み / Saved。古い編集版の成功を新しい版の成功に使わない |
| 古い版は保存済み、最新の編集は失敗 | 最新変更が未保存で、保持中の内容を確認できる | 最新の変更を保存できませんでした / Your latest changes couldn’t be saved. |
| 最新版の本体は成功、native の予備保存だけ失敗 | 最新版の本体保存は成功している | 最新の変更は保存済みです。端末内の予備保存を更新できませんでした / Your changes are saved. The on-device recovery copy couldn’t be updated. |
| 安全確認中 | 保存データをまだ確認している | 確認中を不存在・破損・保存成功へ言い換えない |
| 読込・検査に失敗 | 安全に確認できず、上書きを防いでいる | データがないと断定せず、再確認・原文取り出しへ案内する |
| 有効な0件の保存版 | その版にメモがない | この保存版にはメモがありません / This version contains no notes. 削除した人・理由・履歴や「候補なし」を推測しない |
| 1つの版に3件のメモ | `noteCount = 3`、`versionCount = 1` | This version contains 3 notes. 「3つの復元候補」としない |
| 候補の閲覧 | 表示対象を切り替えて比較している | 別の保存版を表示しています / You’re viewing another saved version. `View` を保存成功と訳さない |
| 候補の採用と保存 | 明示選択した内容を使い、保存結果を確認する | 採用操作の直後に無条件で「保存済み」としない。失敗時は未保存と選択した内容を保持する |
| 原文のコピー成功 | 全文をクリップボード API へ渡し、成功を確認した | コピーしました / Copied。アプリ内保存・別端末への移行・永久保管の成功ではない |
| 原文のコピー失敗 | 自動コピーできなかった | 全文の手動選択を提示する。抜粋に置き換えない |
| 通常のメモ削除 | 直前の1件だけ、10秒以内、終了・再起動前なら Undo できる | `a short while` のように時間と範囲を曖昧にしない。削除保存の失敗は別に表示する |
| 保護候補の整理 | 確認した候補を選んで削除する。取り消せない | 通常メモの Undo が使えるように読ませない。コピーと対象確認を先にできるようにする |
| 描画例外からの下書き救済 | RAM に保持できた内容をその場で読む・コピーできる | 再読み込みで未保存内容が失われ得ることを伝える。「再起動しても残る」と言わない |

0件の候補を採用すると、採用対象の集合が空になることを確認操作で説明する。一方で、表示してみるだけの操作に上書き確認を付けて、実際には何もしない操作を破壊操作のように見せない。

確認者には内部の保存先名を先に教えず、合成画面から「今どの内容が保存されているか」「このボタンで何が変わるか」「失われる可能性があるものは何か」を説明してもらう。自然な文章でも、この3点を取り違えるコピーは再確認へ戻す。確認は [fixtures/round-2.json](fixtures/round-2.json) の `MRS01`〜`MRS04` と、現行の保存異常 `F01`〜`F08` を使う。

## 4. 辞書の型・引数・抽出範囲

### 型を文言の値から独立させる

日本語の `as const` の値をそのまま英語の型にすると、日本語の文字列リテラルを要求する型になり得る。共通のメッセージ契約を先に置き、各辞書をその契約で検査する。以下は構造例であり、この文書でコードを追加したものではない。

```ts
type UiLocale = "ja" | "en";
type Messages = {
  newNote: string;
  recoveryVersionNoteCount: (args: { noteCount: number }) => string;
  deleteUndoNotice: (args: { undoSeconds: number }) => string;
};

const en = {
  newNote: "New note",
  recoveryVersionNoteCount: ({ noteCount }) =>
    noteCount === 1
      ? "This version contains 1 note."
      : `This version contains ${noteCount} notes.`,
  deleteUndoNotice: ({ undoSeconds }) =>
    `You can undo the last deletion for ${undoSeconds} seconds, before the app closes or restarts.`,
} satisfies Messages;
```

型検査はキー・引数の不整合を減らすが、翻訳の正しさ、空文字、古い訳、表示の欠けは保証しない。これらは台帳・到達画面・受入試験で検査する。

| 引数 | 意味と制約 |
|---|---|
| `noteCount` | 1つの集合に含まれるメモ数。0は有効。`null` や候補なしと同じ扱いにしない |
| `versionCount` | 比較できる保存版の数。メモ数と型の名前・文脈を分ける |
| `candidateIndex` | 利用者が識別する候補番号。並び順や表示名だけで永続的な候補同一性を判定しない |
| `undoSeconds` | 説明に使う取り消し可能時間。実際の deadline / timer は翻訳関数の外で保持する |
| `displayDate` | 表示用に整形した日時。保存・ソート・復旧候補選択の入力に戻さない |
| `noteTitle` 等 | 本人の原文または表示用の識別名。辞書キー・HTML・式として解釈しない |

0 / 1 / 2 / 11 / 1000 の件数を確認し、一覧、検索結果、版の中のメモ数を別の message ID にする。`"Found " + count + " notes"` のような文章の断片共有を避け、文全体と名前付き引数を訳す。小規模の日英では型付き関数と `Intl` で足りるため、自作の複雑な ICU パーサーや翻訳 SaaS を前提にしない。[S1]

### 抽出対象

- `src/lib/i18n.ts` の既存コピー、aria・title・状態通知。
- `BrushPicker` と、その筆データの `labelEn`、説明 `note`、見本 `sample`、radiogroup 等。アプリが用意した見本は翻訳対象だが、本人のメモは別である。
- `CopyTextButton` の通常・処理中・成功・失敗・手動選択状態。
- `RecoveryReview` の候補名、0件、件数、日時、全文、採用・整理に関わる説明と確認。
- `AboutScreen` の同梱説明、外部リンク、版番号不明・開発版・リンク失敗。
- `AppErrorBoundary` 等、通常 Provider が壊れていても必要な最小救済コピー。

元メモや HTML らしい文字は React の文字列として扱い、翻訳の差し込みに `dangerouslySetInnerHTML` を使わない。`MLT22` の `<em>` や `{noteCount}` が本人の題名に入っていても、タグや翻訳パラメータへ変わらないことを確認する。

## 5. 翻訳を更新し続ける最小工程

### 1つの確認台帳

実装時に、日英辞書に対応する小さな翻訳台帳を1つ設ける。保存形式はリポジトリで差分確認できる JSON 等でよく、新しい外部サービスは必要ない。

| 台帳の項目 | 記録する内容 |
|---|---|
| message ID | 文言の位置ではなく意味を追跡する安定した ID |
| 原文・訳文 | 現在の日本語と英語。空訳・未訳を明示する |
| 引数契約 | 名前、型、単位、0・不明・複数の意味 |
| 表示条件 | 状態・対象編集版・保存結果など、何を確認した画面か |
| 操作の結果 | 閲覧、採用、書込み、コピー、破棄のうち何が起きるか |
| 到達範囲 | 初版必須 / 無効機能 / 開発用 |
| 確認状態 | 未訳 / 要再確認 / 文言確認済み / 実画面確認済み |
| 確認 fingerprint | 原文・訳文・引数契約・意味説明を合わせた内容の識別値 |
| 証拠 | 対象コミット、画面・状態、言語、倍率、確認者、日付 |

原文、訳文、引数、表示条件、操作の意味のいずれかが変われば、以前の承認を現在の確認として使わず **要再確認** にする。fingerprint は古い証拠の再利用を検出する補助であり、コードの意味の変更を自動で理解する仕組みではない。ボタンの動作や保存状態を変える実装では、対応する意味説明も更新する。

Apple String Catalog の New / Needs Review / Stale は管理の参考になるが、Xcode がこのアプリの TypeScript 辞書を自動抽出・確認しているとは扱わない。[S2]

### リポジトリでの確認

[翻訳台帳](translation-ledger.json) のIDは [日英辞書](../../src/lib/i18n.ts) と [静的救済の辞書](../../src/i18n/rescueMessages.ts) を参照します。原文・訳文・型・表示条件と意味・公開ページの該当原稿をグループごとに指紋で照合します。`npm run copy:check` は通常のCIの一部です。意味を変えたときは台帳の契約を編集し、`node scripts/check-copy.mjs --refresh` で承認を要確認に戻します。独立校閲と画面確認の証拠を記録し、公開候補は `npm run copy:release` を通します。現時点は8グループとも承認待ちです。

### 翻訳・確認へ渡す単位

単独の語句だけでなく、見出し、主文、補足、隣のボタン、操作前後の状態を1セットにする。合成データの画面を添え、撮影したコミット・UI 言語・文字倍率・保存状態を記録する。復旧画面は `noteCount` が「1版の中のメモ数」であること、0件も有効であること、日時が新しい候補を必ず正しいと扱わないことを添える。

実ユーザーのメモを校閲の素材にしない。原文に短い値・長い値・空値・混在方向の値を用意し、可視ラベルと accessible name の関係、フォーカス順、折返しも確認する。英語校閲の担当や完了日が決まっていないものは、未校閲として残す。

## 6. 完成言語と fallback の公開条件

公開言語は明示的な allowlist で管理する。日英完成版は `ja` / `en` のみで、辞書ファイルの存在から選択肢を自動生成しない。疑似翻訳・下書き・将来言語は製品の選択肢、native 宣言、Store の対応言語説明へ出さない。

**同梱・公開する単位は、1言語の通常画面＋異常系＋最小救済＋同梱情報ページの一式**。辞書をネットワークから取得しなくても、機内モードで切替・説明・全文取り出しへ到達できることを必要とする。

| 段階 | 必須の扱い |
|---|---|
| 開発・CI | 公開必須の欠落、空訳、引数不整合、要再確認、古い fingerprint を検出する |
| 文言・実画面レビュー | 未確認を見える状態で記録する。fallback で表示できたことを確認済みにしない |
| 実行時の想定外エラー | 確認済みの最小救済コピーへ到達させる。通常 Provider・複雑な formatter への依存を避ける |
| 公開判定 | すでに公開した言語の訳が追いつかない場合は、そのビルドの公開を止めて揃える。勝手に対応言語から外さない |

最小救済コピーも正本の辞書・台帳で追跡し、通常 UI と独立した手書きの別訳が放置される構造にしない。解決済みの `ja` / `en` が使える場合はその言語を使い、言語解決自体に失敗した場合は完成後の既定 `en` を使う。重要な説明・対象・破壊操作は一式で扱い、日本語の理由と英語の削除ボタンを偶然混ぜない。

fallback は実行時の救済である。**fallback があること、英語文字列が存在すること、型検査に通ることのいずれも、翻訳完成の証拠にしない。**

## 7. 言語設定、native、最低対応 OS

### 初版の設定実装方針

既存の筆設定と同様の小さな adapter を使い、メモ保存とは別に `zanshin.prefs.ui-language.v1` と `zanshin.prefs.reading-mode.v1` を扱う。コンポーネントから直接保存先を操作しない。初版では Capacitor Preferences を追加しない。設定保存失敗で本文の dirty 状態・保存キュー・復旧ガードを止めない。

UI の希望値は `system` / `ja` / `en`。解決順は、明示した `ja` / `en`、`system` の native アプリ言語または Web の優先言語、最後に完成済み `en` とする。native は `Bundle.main.preferredLocalizations`、Web は `navigator.languages` を先頭から評価する。端末の言語を取るだけのために Device plugin を追加しない。

`system` を今の解決結果で上書きしない。未知の将来値を旧版が読む場合は、その希望値を保持したまま安全な実効言語へ戻す。利用者が明示的に選び直した時だけ新しい希望を保存する。UI 設定の互換処理を `Note.locale` の正常化へ広げない。

アプリ内の変更は辞書の差替えで反映し、App、Provider、入力 DOM の再マウントやページ再読み込みをしない。縦横の設定はアプリ共通の1つで、メモごとの新設定は作らない。既存選択を優先し、旧利用者は従来表示を引き継ぎ、新規導入のみ日本語なら縦・英語なら横を一度だけ初期化する。メモ0件を新規導入の証拠にしない。英語を公開する条件として、横書き読書を完成させる。

### native 宣言を変える時点

| 対象 | `4ec10d1` の状態 | 日英完成後の状態 |
|---|---|---|
| `CFBundleLocalizations` | `ja` | `ja`, `en` |
| `CFBundleDevelopmentRegion` | `ja` | `en` |
| Xcode `developmentRegion` | `ja` | `en` |
| `knownRegions` / native の翻訳リソース | 日本語を基準に確認する | `ja`, `en`, `Base` と、実際のリソースを整合させる |
| アプリの実効 fallback | 日本語 UI の現行実装 | native と Web と最小救済で `en` に揃える |

native bundle の宣言、TypeScript の UI 辞書、Store メタデータは別の設定である。いずれか1つを変えただけで全体の言語が切り替わるとは扱わない。[S3][S4]

独自のアプリ内 override は native のアプリ言語を書き換えない。選択メニュー、キーボード、OS が提供する画面の言語とアプリ UI が異なる組合せを確認する。現行で存在しない権限要求を試験のために追加しない。

OS 設定だけを使う案は原調査の参考案であり、**日英初版では採用しない**。今回採用したアプリ内の `system` / `ja` / `en` を、実装者の判断で OS 設定だけの方式へ差し替えない。

機能として OS 設定への案内を設ける場合は、移動で終了・再起動が起こり得るため、案内前に現在の編集版の保存結果を確認する。保存失敗・競合中は全文取り出しと移動中止を提示し、保存できていない内容が再起動後に残ると説明しない。native bridge や Settings への遷移は、実装・実機確認が必要である。[S5]

### iOS 14.0 と Unicode API

現在の `IPHONEOS_DEPLOYMENT_TARGET` は `14.0`。これを新しい SDK でビルドする要件と混同しない。提出用 Xcode / SDK の条件は提出時に公式情報で確認し、最低実行 OS は別に記録する。

`Intl.Segmenter`、Unicode property escape、`Intl` formatter 等は、採用する各処理について最低対応環境で確かめる。`Intl.Segmenter` 不在でも起動できるだけでは不十分で、抜粋・文字数の境界が ZWJ・結合文字・旗を分断しないかを確認する。現在の `Array.from` 代替はコードポイント単位であり、この保証を満たす一般的な書記素分割ではない。

日英初版は、正しく書記素分割できない環境では JS で原文を短縮せず、CSS での表示省略と全文への経路を使う。正しい題名文字数を計数できない場合は、目安の案内を省ける。将来、厳密な計数のために代替実装が必要なら、用途・依存範囲・最低 OS の結果を確認して採用する。理由なく最低 OS を引き上げたり、200文字目安のために未確定文字を切り落としたりしない。

題名の200は、書記素の目安とし、保存原文を強制切断しない。既存の長い題名も有効な内容として開き、編集・戻る・言語変更だけで切断しない。厳密な保存上限が別途必要になった場合は、容量・性能、IME 確定後、貼付け超過時の取り消しまでを別仕様として決める。

現在の題名 `textarea` は、意味上は一行で、見た目は折り返して高さを持つ入力として扱う。IME 外の Enter で本文へ移る既存操作を保ち、実際の題名編集時に受け取った改行を空白へ置換する契約を明記する。既存の題名を読み込んだだけでは書き戻さない。本文は実際の編集時に textarea が受け取った LF を保存し、救済コピーの元は題名・本文とも保持しているモデルにする。貼付け前の外部バイト列まで、すべての OS で完全に同一とする保証には広げない。

## 8. 地域書式、英語、後続言語

初版は共通 `en` を使い、en-US / en-GB の辞書を丸ごと複製しない。用語は上の操作語へ揃え、綴りは米式を編集上の基準とする。これは端末地域を米国へ変更する意味ではない。地域差が必要になったキーのみ、将来の差分として扱う。

ブランドの日付印は `YYYY.MM.DD`、グレゴリオ暦、`0123456789` を維持する。詳細日時・読み上げの locale は実効 UI の `ja` / `en` に揃え、こちらもグレゴリオ暦・Latin 数字を明示する。初版の表示は端末の現在のタイムゾーンを使う。将来 en-US / en-GB や利用者の地域設定へ拡張する場合も、書式だけの選択とし、保存タイムスタンプ、ソート、復旧比較、タイムゾーンを変えない。空の版に存在しない変更日時を推測して表示しない。[S6]

`en-GB` の入力から `en` を解決できることと、英国書式が選ばれることは別の試験である。Node の `Intl` 参考結果は、iOS の設定が WKWebView へどう反映されるかを確認した証拠ではない。

後続言語を allowlist へ追加する条件は次の一式とする。

1. 操作・保存・復旧・削除・例外・情報ページの訳と文脈が確認済みである。
2. 文字拡大、最小画面、入力方式、font fallback、読み上げを対象文字体系で確認している。
3. RTL の UI を公開する場合は、本文の `dir` だけでなく、全体の配置・戻る操作・数字・アイコンを別に確認している。
4. native 宣言、Store メタデータ、最終画面、同梱/公開ヘルプの対応範囲が一致している。
5. 旧版が未知の希望言語を読んでも、本文や元の希望値を破壊しない。
6. 問い合わせ窓口で実際に案内できる言語・対象版を説明できる。

日本語・英語 UI でアラビア語やタイ語のメモを扱えることを、それらの UI、音声、検索の言語解析、問い合わせまで正式対応したという宣言にしない。

## 9. App Store、ヘルプ、サポートの揃え方

App Store Connect の primary language は日本語のままでもよい。Store ページのローカライズとバイナリが対応する言語は別であり、`en` 辞書の追加を理由に primary language を変更する必要はない。Store が用意する英語の地域別メタデータ区分を、アプリ内辞書の複製単位にしない。[S4]

| 公開面 | 日英版で必要な確認 | 外部条件・未確定事項 |
|---|---|---|
| 実 UI | 公開必須の通常・異常画面を日英で完成させる | ML01〜ML44 の証拠が必要 |
| native Archive | 最終 Archive の言語宣言・リソース・実効 fallback を照合 | Xcode / 署名 / Archive / 実機は別途実行する |
| Store の説明 | 実搭載の保存・読書・検索・無料方針を説明する | 管理画面への登録・提出はこの設計作業では行わない |
| スクリーンショット | 同じ最終候補ビルドを日英へ切り替えて撮影する | Web の再現画像を実 iPhone / Simulator の実績と呼ばない。旧版・合成の未搭載画面を使わない |
| 同梱 About / Privacy / Support | 通信なしで日英の保存・削除・予備保存・問い合わせ説明へ到達する | 既存の日本語説明も最新の動作と照合する |
| 公開 Privacy / Support | 対象版と対応言語が分かり、サインイン不要で読める | 公開 URL の設定・ホスティングは実在を確認する。未設定を公開済みにしない |
| 問い合わせ窓口 | 実際に管理している連絡先と、公開/非公開の性質を説明する | GitHub Issues 以外の非公開窓口は未設定。メールアドレスを作ったことにしない |

プライバシー説明では、アプリがメモを独自サーバーへ送らないことと、利用者が有効にした iOS の端末バックアップにデータが含まれ得ることを区別する。端末内の予備保存を、クラウド同期や機種変更後の復元保証として案内しない。ポリシーのアプリ内・Store からの到達要件は提出時にも再確認する。[S7]

英語ページを用意しただけで、英語の返信体制や返信期限を約束しない。サポートにはアプリ版、表示言語、機種・OS、起きた操作、表示されたメッセージを任意で添えられるようにする。本人のメモの添付を必須にしない。現在の GitHub Issues は公開であることを明記する。

ヘルプは対象版を持ち、Undo 時間、復旧の操作、保存説明を変えたら対象版と翻訳の確認状態も更新する。翻訳の報告は message ID とビルドへ結び付ける。公開ヘルプを更新しても、旧版に同梱した説明が更新されたことにはならない。

## 10. リリース前の判定

**設計収録済み → 実装済み → 機械確認済み → 文言/実画面確認済み → 実機確認済み → 提出候補** を区別して記録する。現在の文書追加は最初の段階である。

日本語の既存258テスト成功は、日英版の合格ではない。少なくとも保存・復旧の意味、言語切替中の原文保持、英語横書き、最低対応 OS の文字分割、実機 IME / VoiceOver、native / Store / ヘルプの整合が必要になる。実機や管理アカウントがない間も、実装・自動確認・文案・撮影準備は継続し、未実施項目を [ACCEPTANCE.md](ACCEPTANCE.md) に残す。

この文書は、製品実装、署名、アップロード、TestFlight 配信、Store 提出、公開ヘルプの外部公開を実施した記録でも、それらを自動で実行する指示でもない。必要な外部操作は、その時点の利用者の指示と環境に従う。

## 11. 一次資料と設計判断の区別

以下は調査時（2026-11-26）に参照した一次資料。台帳、用語、初版の辞書単位、独立 adapter、200文字目安などは本プロジェクトの設計判断であり、各資料がその実装を要求しているわけではない。提出時の変わり得る要件は再確認する。

- [S1: W3C — Working with composite messages](https://www.w3.org/International/articles/composite-messages/): 文章の断片・差し込みと翻訳の文脈。
- [S2: Apple — Discover String Catalogs](https://developer.apple.com/videos/play/wwdc2023/10155/): 翻訳の状態・コメント・再確認の管理。
- [S3: Apple — Bundle.preferredLocalizations](https://developer.apple.com/documentation/foundation/bundle/preferredlocalizations)、[CFBundleLocalizations](https://developer.apple.com/documentation/bundleresources/information-property-list/cfbundlelocalizations)、[CFBundleDevelopmentRegion](https://developer.apple.com/documentation/bundleresources/information-property-list/cfbundledevelopmentregion): native の言語選択と宣言。
- [S4: Apple — Localize app information](https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information/)、[App Store localizations](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations): Store メタデータの言語。
- [S5: Apple — Creating Great Localized Experiences with Xcode 11](https://developer.apple.com/videos/play/wwdc2019/403/): アプリ別言語と設定移動。独自 bridge の作り方は [Capacitor v7 — Custom Native iOS Code](https://capacitorjs.com/docs/v7/ios/custom-code) を参照する。実装・実機結果は別に記録する。
- [S6: ECMA-402](https://402.ecma-international.org/): Intl の locale、書式、暦、数字、タイムゾーン。書記素の仕様は [Unicode UAX #29](https://www.unicode.org/reports/tr29/) を参照する。
- [S7: Apple — App Review Guidelines, Privacy](https://developer.apple.com/app-store/review/guidelines/#privacy): アプリのプライバシー説明と到達経路。
- [WHATWG — textarea](https://html.spec.whatwg.org/multipage/form-elements.html#the-textarea-element)、[maxlength](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#attr-fe-maxlength)、[Infra — string length](https://infra.spec.whatwg.org/#string-length): 入力値・改行・UTF-16 制限。既存の保存文字列まで勝手に正規化する根拠にはしない。
