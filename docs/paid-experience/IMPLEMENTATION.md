- `src/lib/storage.ts`、`nativeDurableSnapshot.ts`、`draftRescue.ts`、`src/types/note.ts`、`ReadMode.tsx`、`brushPreference.ts`、`src/main.tsx`、`src/release.css`、`featureFlags.ts`、`monetization.ts` を現行コードで確認する。
- [日英対応の設計](../multilingual/DESIGN.md)・[実装指示](../multilingual/IMPLEMENTATION.md)と共通化する辞書、言語設定、読書方向、Unicode処理を特定する。実装済みなら再利用し、未実装なら必要な共通基盤を同じ契約で整える。公開完了判定はI/ML側にも証拠を残す。
- 無料一冊、新規複製、復元済み複数冊、権利取消後の既存編集を、操作別の権限表にする。BookRepository全体を購入判定で停止しない。

日英基盤が未実装の場合は、P0でI0の棚卸しとI1の共通基盤を整え、P2までに必要なI2の読書・入力を統合します。I3の保存・復旧・救済、I4の情報・native宣言・掲載準備も対象とし、P6でI5とML01〜ML44の結果・残件を併記します。「綴り」の新画面だけを日英化して、アプリ全体の日英対応を完了としません。実機待ちを理由に、それ以外の実装を止めません。

既存の広告削除モックやlocalStorageのbooleanを本番権利へ昇格させません。商品ID案を実商品と偽らず、日英初版のフラグを先に有効化しません。開発用の検証経路が必要なら、製品版に出ない構成として明示します。

## P1 — 原文を守って一冊を保存する

DESIGN 10・13の契約を先に実装します。既存 `zanshin.notes.v1` へ冊子や画像を足しません。関連するBook・BookEdition・BookDraft・TextSnapshot・SavedPresetの確定はBookRepositoryで管理し、既存メモのjournal、競合、native世代保存を維持します。

### 最小で成立させる動作

1. 保存状況を確認した実際のメモを選び、文章の写しと順序をBookDraftへ保持する。
2. 最終の「綴じる」前に本人が確認した文章を不変のTextSnapshotとして確定する。選択・購入中の元メモ変更を黙って混ぜない。
3. 基本紙・既存筆あと・無地表紙の一冊を保存し、再起動後にも同じ文章を読めるようにする。
4. 元メモの編集・削除、冊子内だけの編集、元メモ更新の採用、別冊子への複製を別操作として扱う。
5. UTF-8原文取り出しと、保存済みメモ・冊子・保存済み下書き・保持対象過去版・参照snapshot・由来・読書位置・自分の仕立てを含むJSONの書き出しと検証付き復元を実装する。後続工程でSavedPreset等が利用可能になった際も同じ契約に含める。
6. メモのみ、冊子のみ、全データの削除対象を分離する。

各篇の `textSnapshotId` と `sourceBaseSnapshotId` / `sourceContentHash` を分けます。元メモの変更検知に冊子内修正版のhashを使いません。両者が変わったときは前回の元メモ・現在の冊子・現在の元メモを比較し、他の冊子や履歴のsnapshotを書き換えません。

復元は全参照を検証してから反映します。複数の保存先にまたがる場合はjournalを設け、部分成功を全完了と扱いません。新しいschema、同じIDの別内容、未知素材、未解決の保存障害はそれぞれ区別します。購入権利をJSONから復元しません。

全データ削除は新規書込みを止め、実行中・待機中の書込みを完了待ちまたは無効化したうえで、予備保存・復旧候補・管理中の一時出力も対象にします。中断を越える削除マーカーを保持し、起動時の通常復旧より先に削除を再開します。利用者が外へ保存したファイルやAppleの購入記録まで削除できるとは説明しません。

### 検証と次へ進む条件

不変snapshot、元メモとの三者比較、旧版による上書き、nativeの遅い書込み、容量不足、途中終了、JSON往復、取消後編集、全削除中の終了を優先して確認します。未保存内容と直前正常版を守れる状態にしてP2へ進みます。既存のメモ保護を外して冊子保存だけを通す変更はしません。

## P2 — 読んで持ち出せる基本の一冊

「言葉を選ぶ → 仕立てを選ぶ → 綴じて読む」の三段階を実際のメモで通します。題名・署名・作者名・最低文字数を必須にしません。見本だけで画面を成立させず、一行、無題、長文、日英混在、先頭末尾の空白を含む原文を使います。

- 基本の綴じ本、目次・栞・戻り先、ドラッグ以外の並べ替えを用意する。
- 文字拡大に応じる読書と、固定寸法の出力見本を分ける。読書位置は篇と文字位置へ結びつける。
- 無料の全文PDFを完成させる。文字選択・検索、正しい順序、約物、ページをまたぐ長文、埋め込み許諾を確認する。
- 画像試作は範囲と寸法を示す。一枚に収まらない文章を黙って省略・縮小しない。
- 編集中なら「変更を保存して書き出す」で版を確定する。出力処理が参照するedition・素材・組版バージョンを固定し、途中の編集を混ぜない。
- 基本PDFへ切り替えても、冊子に保存した有料素材IDを上書きしない。OS共有のキャンセルを保存成功と表示しない。

P0〜P2の最初の区切りは、実際のメモから冊子保存・再読・基本PDF・JSON復元まで成立した状態です。ブラウザの印刷ダイアログだけを置き、iOSの出力方式を未検討にしたまま完成扱いにしません。実機がない場合はその未確認を残してP3以降の実施可能な作業へ進みます。

## P3 — 紙・筆あと・装丁・仕立てを制作する

DESIGNのPA01〜PA08、BR01〜BR04、CV01〜CV06、ST01〜ST06を安定IDとして扱います。色替え、ウェイト違い、同じ描画の名称違いを別素材数へ水増ししません。

素材は本人の文章・標準のかな漢字欧文・長文で比較します。紙は地色を弱めた比較と既存無料紙との比較を行い、繊維・目・端などの違いを確認します。乱数模様はseedを固定し、文字入力や再読で揺らぎません。本文や操作の実背景上で可読性を確かめます。

字体は候補の実ファイルを取得して権利・字種・縦横・PDFを確認します。Yuji Maiの共通漢字を独自の新字体と説明せず、Yomogiを小さい長文の既定にしません。未対応文字を空白にせず、代替字体を出力前に確認できるようにします。許諾のないOSフォントを抽出・配布しません。

追加の紙と筆は、普段の入力・読み返しと一冊ごとの設定に適用します。日常の設定変更が既存冊子へ波及せず、入力字体を読みやすいものへ残す選択ができるようにします。共通の操作・復旧説明まで装飾字体へ置き換えません。

まず本人の文章を入れた完成仕立てを見せ、詳細調整を任意にします。有料条件はプレビュー前に示し、無料の仕立てへ戻る経路を用意します。入力・保存・復旧へ購入を割り込ませません。

各素材に採用結果、ファイルバージョン、ライセンス表示、比較画像、容量・実測対象を残します。採用できない候補はDESIGNと仕立ての対応表を同時に更新し、未検証候補を数だけ揃えて発売しません。

## P4 — 三形式と見本を完成させる

綴じ本の連続読書に加え、折本の一面／全体表示、一葉帖の一篇／複数枚を完成させます。折本を実際に折れる特殊面付けPDFと説明しません。一葉帖の長文は複数枚やPDFへ出し、抜粋なら本人の選択範囲を示します。

この工程で一篇画像の正式出力と、有料素材を使う文集・印刷向けPDFを完成させます。P2の試作のまま残さず、P5で操作別の購入権利と接続し、P6で実機と生成物を最終確認します。

オリジナルの見本二冊は利用者のデータと区別し、無料自作一冊の枠を使いません。見本は非表示・削除でき、自作を見本として保存し直す抜け道を作りません。保存した仕立てには本文を含めず、権利取消でも設定情報を削除しません。

全形式で大きな文字、操作名、VoiceOver、動きを減らす設定、読書の戻り先を確認します。装丁演出を保存成功表示や画面遷移の前提にしません。10篇・100篇、2,000字・10,000字で全文に到達できること、プレビューと出力のメモリを確認します。

## P5 — 本番購入と制作の境界を実装する

実際の提供範囲と商品定義を揃えたうえで、非消耗型のStoreKit購入・復元・権利確認を実装します。`zanshin.tsuzuri` は登録確認までは候補であり、表示価格はStoreKitから取得します。旧 `zanshin.premium.remove_ads` やmock booleanを新商品の購入済み状態へ転用しません。

権利判定は操作ごとに行います。既存冊子の題名・本文編集、元メモ更新の採用、篇の追加・削除・並べ替え、その新しい版の保存、原文取り出し、基本PDF、バックアップと復元は利用可能に保ちます。既存複数冊を一冊へ減らさせません。新規冊子、別冊への複製、有料素材の新規適用、有料形式の新規出力はDESIGNの境界で判定します。

無料の通常新規作成は自作0冊のときに許可し、削除後はまた作れます。プレビューに回数・期間制限を付けず、復旧用draftの保存を有料完成冊子と表示しません。

商品取得中・失敗、購入成功・キャンセル・承認待ち、復元・一時的な通信障害・正式取消を別状態にします。通信不良だけで直ちに権利喪失とせず、既存の検証済み権利を扱います。成功・中止後は同じ文章・選択・プレビューへ戻します。購入復元と文章の復元を混同させません。

StoreKitの検証は、シミュレーション・Sandbox・TestFlightを分けて記録します。権利基盤が完成するまで販売用フラグを有効化せず、開発用の模擬購入を製品画面へ出しません。App Store Connectの実商品登録や配信操作は、その時点の依頼とアクセス可能範囲で実施します。

## P6 — 提供内容と見える約束を一致させる

AC01〜AC26の全項目、変更が影響するR項目、日英のML項目を同じ候補コミットで確認します。ja/enは通常画面だけでなく、保存失敗、復旧、購入、復元、出力、権利取消まで揃えます。本文翻訳・外部フォント配信・解析サーバーへの本文送信を追加しません。

375×667相当から大きいiPhoneまでの紙面、200%相当、Dynamic Type、VoiceOver、キーボード、バックグラウンド復帰、低メモリ・容量不足、オフライン、画像共有、PDF全文を実機で確認します。Webの描画結果をWKWebViewやOS共有の合格へ流用しません。

購入画面・アプリ情報・ストア草案・スクリーンショットに、実際に完成した素材数、利用可能範囲、買い切り、取得した価格の意味を反映します。既存初版の「課金なし」を無関係な版まで消さず、対象の有料対応版の説明として更新します。原資料のApple要件・字体ライセンスも採用・販売時点で再確認します。

最後に、見た目の完成と支払意思を分けて確認します。本人の文章で一冊を作れるか、もう一冊作りたいか、1,800円の仮説を購入対象として選ぶかを確かめ、未測定の購入率を実績扱いにしません。

## 検証・引継ぎの形式

既存 `npm run check` とCIを維持します。テストは不変snapshot、版の競合、復元、権利の境界、全削除、出力一致など、誤ると文章や意味が変わる箇所へ重点を置きます。名称やCSS値をそのまま期待値にしただけの試験で体験品質を合格にしません。

各工程の報告には次を含めます。

- 対象コミット、P段階、実装した体験、変更ファイルと判断理由。
- 実行したコマンドと結果。標準コマンドの失敗を一時設定の成功で上書きしない。
- AC別の実装状況と証拠。Web・実機・StoreKit・生成物・校閲を区別。
- 採用素材、権利表示、出力見本、原文一致の確認結果。
- 未実施事項、その必要環境、次の担当者が再現できる手順。

実機やApple環境がなければ、その確認だけを未実施として記録します。実装、自動確認、情報ページ、掲載草案、復元・購入・出力の再現手順まで進めてください。未確認を合格にせず、公開・配信開始・本番デプロイはこの設計引継ぎだけを根拠に実行しません。
