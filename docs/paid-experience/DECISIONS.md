# 実装の判断

起点は日英対応を統合した `e99a80f`。着手時の作業ツリーに未保存差分はありませんでした。既存のi18n Provider、共通の読書方向と本文描画、Unicode検索、4種類の筆あとを再利用します。メモの本体・journal・世代予備保存・競合候補・例外救済を維持します。旧広告削除のフラグとモックは綴りの権利判定では参照しません。

## 保存と出力

冊子の本体、保持対象の過去版、下書き、写し、自分の仕立てはIndexedDBで版を比較してまとめて確定します。iOSの冊子予備はメモとは別ファイルです。JSON復元のメモと冊子にまたがる処理は、冊子側で処理記録を確定してから既存メモの版比較付き書込みを通します。全削除は独立したマーカーを置き、開始前の画面からの新規保存を拒否します。

印刷ダイアログのみに依存する案と、端末でPDFを生成する案を比較しました。紙面プレビュー、PNG、PDFの見える文字は同じCanvas組版を使い、PDFには絵だけでなくUnicode原文の検索・選択用テキスト層と埋め込みフォントを付けます。用紙寸法を固定できる一方、PDFビューアによって縦書きの選択順や検索に差があり得るため、生成物の確認を別途記録します。原文そのものはTXT・JSONでも持ち出せます。
