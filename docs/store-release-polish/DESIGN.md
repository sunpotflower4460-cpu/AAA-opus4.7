### すべての画面に通す約束

- 作成操作は **「メモを書く」**、題名欄は **「タイトル（任意）」**、編集操作は **「編集する」**。戻る操作は「一覧へ」「検索結果へ」「読み返しへ」のように行き先で呼びます。
- 「言葉を置く」「余白」「余韻」はブランドの文章に残せます。同じ操作に別名を混ぜません。保存・削除・復旧では、起こることを直接伝えます。
- 本人が書いた題名と本文を、自動で要約、清書、空白除去、改行結合、全角半角変換しません。空判定・検索・一覧用抜粋と保存原文を分けます。
- 余白は読む・書くことを支えます。透明な装飾、重複した説明、固定領域によって、入力や復旧確認の場所を失わせません。
- 「保存済み」は現在の変更に対する事実です。以前の版が保存されていることを、現在の文章の保存成功に置き換えません。
- 操作不能の理由、失敗時の次の行動、元の場所への戻り方を、画面と読み上げの両方で伝えます。

## D01 — ホームは空・通常・検索の3状態にする

### 共通構造

上から「アプリ名とアプリ情報への入口」「検索」「件数と必要な状態」「メモまたは空表示」を置きます。主要な作成操作は共通の位置に一つ置き、表示名と読み上げ名を「メモを書く」に統一します。空状態だけに別名の作成ボタンを重ねません。

通常の初期案では、作成操作を画面下部の共通領域に置きます。ボタンの文字を常時読めるようにし、プラス記号だけで意味を推測させません。最後のカード、Undo、下部の説明がボタンとホームインジケーターに隠れない余白を確保します。文字拡大時に同じ固定配置が成立しなければ、操作領域を折り返すかレイアウトへ組み込みます。

「このアプリについて」はホームから直接見つけられる副操作にします。スクロール量やメモの件数に依存して入口が失われない配置とし、入口の装飾を主要な作成操作より強くしません。

| 状態 | 出すもの | 配置の契約 |
|---|---|---|
| 空：検索しておらず、確定したメモが0件 | 小さなアプリ名、短い導入、作成操作、自動保存の一文 | 初回と全件削除後に同じ表示を使える。導入を読むことを操作の条件にしない |
| 通常：メモが1件以上、検索していない | コンパクトなアプリ名、検索、件数、本人のメモ | 大きな説明短冊を毎回先頭に置かず、メモへ早く届く |
| 検索：空白を除く検索語がある | 検索語、結果件数、一致箇所の分かるカード | 通常状態と検索欄・作成操作の位置を揃え、検索のたびに画面全体を組み替えない |

空状態の固定コピーは、例えば次の2文を使います。

> ひとことでも、途中のままでも。  
> 入力した内容は、この端末に自動保存されます。

ブランドコピー「書いたあとにも、心が残る。」を採用する場合も、同じ画面に意味の重なる長い導入を追加しません。作成 CTA を押す前に説明画面を通す導入ツアーは不要です。

検索結果0件は「この言葉に一致するメモはありません」「別の言葉でも探せます」と表示します。未作成の空状態と混同させず、既存の検索クリア操作へ到達できるままにします。

### 状態と完了条件

保存内容の安全確認中は、作成ボタンにも処理中・操作不可の状態を伝えます。何も起きないボタンにしません。検索や既存文章の確認を可能にするかは、確認済みデータの範囲に合わせて D13 の契約で決めます。

375×667 相当の標準文字で、空状態から一度の作成操作で本文へ入れること、通常状態で導入よりメモが主役になること、検索0件からすぐ語を変更できることを確認します。短い画面や文字拡大ではスクロールを許し、文言の縮小で押し込まないでください。

## D02 — タイトルは任意、本文だけでも完結する

### 内容ごとの表示契約

| 保存されている内容 | 一覧の識別見出し | 読み返し | 保存への影響 |
|---|---|---|---|
| 題名と本文あり | 本人の題名 | 題名と本文を全文表示 | 表示調整で原文を書き換えない |
| 題名なし、本文あり | 本文の最初の非空行から作る表示用見出し | 大きな代替題名を挿入せず、本人の本文から読む | 題名欄は空のまま |
| 題名のみ | 本人の題名 | 題名だけで成立させる | 本文が空でも保存可能 |
| 一度も入力・変更していない新規下書き | 一覧へ追加しない | 読み返しを経由する必要はない | 離脱時に正式な空メモを増やさない |
| 既存メモを本人が空にした | 最小限の無題表示と作成日 | 空であることを短く表示 | 自動削除しない |
| 入力後に本人が消した新規メモ | 入力履歴のあるメモとして扱う | 上と同じ | 「現在空だから未操作」と判定しない |

見出しのために本文を題名へコピーして保存しません。無題の一行メモでは、見出しとプレビューに同じ一文を二度出しません。本文もない確定済みメモだけは「名のない余韻」を代替表示として残せます。読み上げでは日付や「本文のないメモ」を添え、同名カードを識別できるようにします。

空判定には trim 相当を使えますが、表示する本人の題名・本文そのものへ trim を適用しません。一覧の短い抜粋は表示上の要約領域として扱い、読み返し・編集・コピーでは原文へ戻れることを保証します。

### 題名の入力と長さ

- ラベルは「タイトル（任意）」にします。プレースホルダーが消えた後も、支援技術から欄の目的が分かる名前を残します。
- 単一行の横スクロールだけに依存せず、折り返して編集できる入力にします。標準文字では2〜3行程度から使える配置を仮目標にし、長い題名は全文へ到達できるようにします。
- 題名の高さ制限によって、別の小さなスクロール枠を増やすことは避けます。大きな文字で行数が増えた場合は、編集画面の共通スクロールに参加させます。
- 現行の上限200は無断で縮めません。現行 HTML の maxLength は UTF-16 コード単位であり、「見た目の200文字」と同義ではありません。上限の数え方を変更する場合は入力検証も含めて別途記録し、既存の長い題名を切りません。
- 折り返しと、本人が入力した改行を区別します。複数行入力へ変更する場合、Enter・貼り付け・IME 確定の扱いを定義し、改行を勝手に削除する後処理を入れません。
- 一覧では原則2行の表示を仮目標にし、省略表示を保存データへ反映しません。読み返しでは題名の全文を読めます。

### 未操作下書きの境界

新規下書きには「今回作った」「まだ利用者が変更していない」という状態を持たせます。既存メモの文字列が空であることとは別です。先頭固定を意図して変更した場合など、本文以外の明示操作も考慮し、入力していた内容を空判定だけで捨てません。

新規作成直後に戻る操作を5回繰り返しても件数が増えず、題名だけ、本文だけ、入力後に消したもの、既存の空メモがそれぞれ契約どおりに扱われることを確認します。

## D03 — 編集中は入力欄とカーソルの場所を優先する

### 二つの表示状態

横書きの編集を維持します。キーボードを閉じている時は、日付、任意の題名、本文が紙の上で落ち着いて見える配置にします。画面キーボードが開いた時は、日付・説明・大きな上下間隔をコンパクトにして、入力と選択に使える場所を増やします。

| 領域 | キーボードを閉じた状態 | 画面キーボードが開いた状態 |
|---|---|---|
| 上部操作 | 行き先名、先頭固定、削除 | 意味とタップ領域を保つ。必要なら折り返す |
| 日付印 | 紙面の補助情報として表示 | 横一行のコンパクト表示を基本とする |
| 空の題名欄 | 任意であると分かる | 大きな空欄にしない。既に入力した題名は隠さない |
| 本文 | 18px 明朝系を基点に、原文を編集 | 同じ入力要素・文字列・選択範囲を維持 |
| 保存状態 | 上部操作に近い一貫した場所 | キーボードの後ろや長い本文の末尾へ追いやらない |
| 紙の装飾 | 静的な背景として配置 | 本文開始位置を占有しない |

空の題名をコンパクトにする場合も、入力欄自体をフォーカス中に破棄しないでください。「タイトル（任意）」へいつでも移れる必要があります。本文が空であることだけを理由に、入力するたびに再フォーカスさせません。

### スクロールの契約

編集画面の縦スクロールの主担当は一つにします。初期案は「安定した上部操作＋その下の編集領域」で、本文の textarea は内容に合わせて伸び、編集領域がスクロールします。ページと textarea が別々に長くスクロールする状態を避けます。

- 本文末尾、途中への挿入、範囲選択、貼り付けに必要な位置へ届くことを優先します。
- 42dvh のような最低高さだけで、キーボード時の配置が成立したと判断しません。外側の最低高さ、Safe Area、上部操作、日付・題名・本文間の余白を合計して評価します。
- 入力中に本文全体を先頭へ戻したり、保存成功のたびにスクロール位置を更新したりしません。
- 大量の文章で自動高さ計算が重くなる場合は、実機計測に基づいて方法を調整します。別のスクロール方式を採用するなら、スクロールの主担当と選択操作が成立することを改めて示します。
- 保存エラーの詳細が長い場合、固定領域を無制限に伸ばしません。短い主文と詳細への操作を分け、詳細画面をスクロール可能にします。未保存である主文は隠しません。

### 375×667 の高さを扱う時の注意

監査時の CSS から、標準文字・Safe Area が各21px以内という条件で自然寸法を足すと、既知の装飾要素の占有を除いても本文の開始まで約304px、本文の最低高さなどを含む全体は約702pxになる概算でした。これは OS の自動スクロール前の計算で、実機の表示位置や見える行数を測った結果ではありません。

「キーボードを出すと常に2行しか見えない」などとは扱いません。改善の仮目標は、標準文字で可能な端末では入力中の前後4〜6行程度を見渡せることです。200%相当の文字では行数を義務にせず、カーソル、必要な文脈、移動操作に到達できることを確かめます。

CSS の svh / dvh が画面キーボードによって常に期待どおり変化するとは限りません。実際の Capacitor / WebView のリサイズ方式と可視領域を確認し、その結果に合わせて調整します。フォーカスがあるだけで画面キーボードが開いていると決めつけず、外部キーボード利用も区別します。

### IME と入力の継続

日本語変換中の DOM の差し替え、key の変更、値の整形、選択範囲のリセットを避けます。Enter を移動や確定操作に使う場合、IME の変換確定を横取りしません。composition handler が無いという理由だけで不具合と判定せず、実際のイベント順序と保存結果を確認します。

新規の「メモを書く」操作後は本文へ入れます。既存メモの編集では、保存の通知や紙の演出がフォーカスを奪わないようにします。入力途中のアプリ切替から戻った場合、確認完了前の自動上書きを避ける保存側の保護も維持します。

日本語かな、英語、絵文字の各キーボード、外部キーボードで、入力・変換・途中挿入・選択・貼り付け・キーボード開閉を確認します。本文末尾がキーボードや下部操作に隠れ続けないことを完了条件にします。

## D04 — 縦書きは文書の流れから組み直す

### 文書と操作の構造

読み返しは日本語の縦書きを初版の基本にします。日付や操作は横書きの外枠に置き、題名と本文を縦書きの自然な文書フローへ置きます。

| 部分 | 役割 |
|---|---|
| 横書きの上部操作 | 「一覧へ」または「検索結果へ」、「編集する」 |
| 横書きの日付印 | 作成日の補助情報。本文の一列の高さを分割しない |
| 縦書き文書のスクロール領域 | 題名、必要なら区切り、本文を DOM 順に並べる |
| 続きの案内 | 実際に続きがある時だけ、控えめに方向を示す |

現在の display:flex と writing-mode:vertical-rl の組合せは、flex-direction の既定値 row により、主軸が縦方向になります。日付・題名・区切り・本文をその子として置くと、一列の高さを分け合う構造になります。overflow の上書きだけを解除して完成としません。

初期実装案は、縦書き文書を通常のブロックフローに戻す方法です。題名が必要な列を使い、その後に本文の列が続きます。題名と本文を flex-shrink で圧縮して収めません。flex を使う場合は、軸と縮小規則の必要性を説明できる局所用途に限ります。

### 物理方向と論理方向

| 意味 | vertical-rl で対応する方向 | 設計上の扱い |
|---|---|---|
| 一つの列を読む方向 | inline 軸、物理的な上から下 | 使用できる高さを決め、文字が列の外で切れないようにする |
| 次の列へ進む方向 | block 軸、物理的な右から左 | 長文を横方向に読み進める |
| 横スクロール | 物理 x 軸 | 続きへ到達するスクロールの主担当 |
| 横方向の余白・列間隔 | block 側の余白 | 題名と本文の間を作る |
| 縦方向の余白 | inline 側の余白 | 一列の使用可能高さを減らすので積み過ぎない |

区切り線の高さと margin-inline を横書き時の感覚で指定しません。監査時の区切りは、最低34pxと inline 方向の余白21px×2で、縦方向に少なくとも76pxを求めていました。区切りを残すなら、通常のブロック境界に沿う薄い線などに置き換え、独立した大きな領域にしません。

横方向の overscroll 制御は物理 x、または縦書きの block 軸に対応させます。inline を指定して横方向を制御したつもりにしません。初版は自由に読み進められる連続スクロールを基本とし、題名と本文の二つの snap point をページ送りとして扱いません。

### 全文へ到達する契約

- 読み始めに文書の冒頭が表示され、右から左へ本文末尾まで進めます。ブラウザごとの scrollLeft の符号を決め打ちせず、実際の到達位置を検証します。
- 文字サイズや画面高の変更時は再配置します。以前の座標へ戻すために本文末尾を読めなくしません。
- スクロール領域の高さは、Safe Area、上部操作、日付を除いた利用可能な高さから決めます。固定の svh 値だけで全画面の成立を判断しません。
- 横スクロールの親に overflow:hidden を一律で掛けません。紙の端の装飾だけを切り抜きます。
- 横方向の続きがない短文には、スクロール案内を表示しません。続きがある場合の文言は「左へ続きます」とし、指をどちらへ動かすかと文章が続く方向を混同させません。
- 案内や薄い端の表示は補助です。それが読めなくても、タッチ・キーボード・VoiceOver で内容へ到達できます。
- 本文の原文の改行と空行は維持します。禁則処理や表示上の折り返しを、保存本文へ書き戻しません。

### 文章の種類と条件付きの横書き

| 内容 | 縦書きで確認する点 | 原文の契約 |
|---|---|---|
| 無題の短文 | 不要な題名や長い空白を足さない | 一行でも完結する |
| 日記 | 段落、空行、末尾までの到達 | 長さを理由に省略しない |
| URL・メール・長い欧文 | 回転、折り返し、選択のしやすさ | 表示の折り返しで文字列を変えない |
| 箇条書き | 数字、記号、字下げの識別 | タスクやリストへ自動変換しない |
| 歌詞・詩 | 意図的な短い行や空行 | 行の結合、均等割付、整文をしない |
| 日本語・数字・英語・絵文字の混在 | mixed の向き、結合文字、句読点 | 全欧文の強制直立や文字の分断を避ける |

**横書きの読み返し切替は条件付きです。** 実機で上記の混在内容を調整しても読みづらさが残る場合に、利用者が「縦書き」「横書き」を明示的に選ぶ小さな切替を採用できます。初版に無条件で追加する必須機能とはしません。内容を推測して途中から向きを自動変更せず、採用した場合も読む向きはメモ原文の変更として扱いません。

<a id="d05"></a>

## D05 — カードは内容を見分け、検索は一致理由を見せる

### カードの情報順序

基本の順序を「識別できる見出し」「必要な原文の抜粋」「作成日と先頭固定のしるし」にします。日付や全カード共通の説明が、本人の言葉より大きな面積を占めないようにします。

カード全体を一つの操作対象として読み返しへ進めます。フォーカスと読み上げ名で操作を伝えられる場合、全カードに同じ「読み返す」の独立した一行を設ける必要はありません。カード内に別のボタンを入れて、button の入れ子にしません。

| 状態 | 見出し | 抜粋 |
|---|---|---|
| 通常、題名あり | 題名の冒頭を原則2行 | 最後の非空行を使う現行の表現を維持できる |
| 通常、題名なし | 本文の最初の非空行 | 見出しと同じ一行を重複させず、別の内容がある時だけ補う |
| 検索、本文に一致 | 上記の識別見出し | 一致箇所とその前後を含む短い原文 |
| 検索、題名だけに一致 | 題名 | 一致箇所が見出しの省略部分なら、その部分を抜粋でも示す |
| 検索、題名と本文に一致 | 題名 | 本文の一致箇所を補い、見つかった理由を明らかにする |

標準時の見出し2行、抜粋2行を仮目標にします。文字拡大時にはカードの高さが増えて構いません。意味のない固定高へ収めるために文字を小さくしません。

### 検索の契約

初版は現行の「検索語の前後の空白を除く」「大小文字を区別しない」という検索範囲を維持し、タイトルと本文を対象にします。空白だけの検索は未検索です。検索用の変換結果を、本人の題名・本文へ保存しません。

全角・半角、かな、互換文字を同一視する追加正規化は条件付きです。採用するなら仕様と検証対象を追加し、検索一致と原文抜粋の位置対応を保ちます。正規化後の文字列位置をそのまま原文の位置として使いません。強調表示は任意ですが、原文と異なる場所を強調しないこと、一致の理由が抜粋から分かることは必須です。

検索クリア後は入力欄へフォーカスを戻し、そのまま次の語を書けます。入力するたびにカードやページ先頭へフォーカスを移しません。結果件数は「N件 見つかりました」、通常件数は「残した言葉 N件」とします。

件数の読み上げは入力が一段落してからまとめます。待機時間を設ける場合、350〜700ms 程度を比較の開始値にできますが、IME の途中や一文字ごとに読み上げを割り込ませないことを優先します。ゼロ件になったことも伝えます。

### Unicode と抜粋の境界

72などの数値で JavaScript の文字列を単純に slice しません。CSS の行数制限、または Intl.Segmenter などによる見た目の文字のまとまりに沿った短縮を使います。API の利用可否は対象 iOS で確認し、使えない時もサロゲートの片側や結合文字を残さない方法にします。

家族・肌色・国旗の絵文字、異体字セレクタ、結合濁点、欧文の結合文字を含め、見出し・抜粋・検索強調・読み上げ用の短縮文のすべてを確認します。表示用の省略記号を本人のメモへ保存しません。

<a id="d06"></a>

## D06 — 戻る先と読んでいた場所を保つ

画面名だけでなく、入り口の文脈を保持します。少なくとも一覧／検索の別、検索語、対象メモ ID、見ていたカード、スクロール位置、復帰させるフォーカスを扱います。読み返しでは文書内の位置、編集では必要に応じて選択位置を保持します。

| 開始地点・状態 | 戻る操作の文言 | 戻り先と復元するもの |
|---|---|---|
| 通常一覧から未操作の新規 | 一覧へ | 作成前の一覧、件数、位置、作成操作 |
| 検索から未操作の新規 | 検索結果へ | 検索語、件数、位置、元の操作 |
| 新規に入力してメモを残した | 一覧へ | 新しいカードが見える通常一覧 |
| 通常一覧から読み返し | 一覧へ | 元のカードとその周辺 |
| 検索結果から読み返し | 検索結果へ | 元の検索語と対象カード |
| 読み返しから編集 | 読み返しへ | 同じメモ、可能な範囲で読んでいた位置 |
| 復旧やアプリ情報から戻る | 実際の行き先名 | 開く前の文脈と、現在の保存状態 |

検索から新規作成した場合、作成時点では元の検索文脈を捨てません。未操作なら完全に元へ戻します。入力して新規メモを残す場合は、新しいカードを確認できる通常一覧へ戻し、終了操作の表示も「一覧へ」にします。現在の検索語に新規メモが一致しないまま、見えないカードを作って終わらせません。

新規のカードへ戻す時は、先頭固定のメモが何件あっても新規カードへ到達させます。通常の「一覧へ」で毎回先頭へ戻す処理と混同しません。入力したメモの保存が未完了・失敗していれば、D12 の案内をそのまま引き継ぎます。

### レイアウトが変わった時の復帰

保存した座標は補助情報です。カード ID や文書内の基準位置を優先し、文字拡大や題名の変更で高さが変わっても、元の内容付近へ戻します。

検索結果から開いたメモが編集で検索条件から外れた場合は、元の検索結果へ戻し、「編集したメモは検索条件に一致しなくなりました」と短く伝えます。元の隣のカードなどへ移り、理由なく先頭へ跳ばしません。削除されたカードは、近傍のカード、結果がなければ見出しや検索欄へフォーカスを移します。

読み返しから既存メモを一文字直して戻る時に、新しい「保存」「完了」「読む」の操作を同時に増やしません。自動保存と行き先を分け、行き先の操作は一つにします。保存の成功演出を待たないと移動できない設計にしません。

<a id="d07"></a>

## D07 — 金のしるしは「先頭に留める」を表す

初版は現行のお気に入り優先の並びを維持します。操作の意味は「このメモを先頭のグループに留める」です。単なる色の好き嫌いの印と、固定位置の操作を混在させません。

| 項目 | 初版の契約 |
|---|---|
| 未選択時の操作名 | 先頭に留める |
| 選択時の操作名 | 先頭固定を解除 |
| 状態の読み上げ | 先頭に固定、選択状態を伝える |
| 一覧順 | 固定したメモを先に、その中と通常グループ内は変更日時が新しい順 |
| 固定の切替 | 題名・本文と同じくメモ全体の変更として、現行の updatedAt を更新する |
| 新規作成からの復帰 | 固定グループの下にある場合も新規カードを見せる |

状態は金色だけに頼りません。印の形・有無と選択状態を持たせ、ボタンには aria-pressed 相当を付けます。金の点や細い線はブランドとして使えますが、目の見える利用者にとっても操作の意味が分かる表示名や近接した説明を用意します。モバイルで出ない hover の説明だけにしません。

小さな図形に合わせて操作領域を縮めず、44×44 CSS px を本プロジェクトの設計目標として確保します。文字拡大で操作名が入らなければ折り返します。固定されたカードの印は独立したボタンにする必要はありません。

**R22 の最終判断：初版では updatedAt の現行の役割を維持します。** 旧監査には、固定の切替で本文の更新日時を変えない案があります。しかし既存の重複 ID の選別と復旧時の統合は updatedAt を参照しており、固定だけ時刻を止めると復旧でその変更を失う懸念があります。今回 contentUpdatedAt の追加や日時スキーマの変更は行いません。

UI は updatedAt を「変更日時」として説明し、「本文を編集した日時」とは呼びません。並び替え、同じメモの固定変更、復旧時の選別がこの契約と一致することを実装側で確認します。詳細は IMPLEMENTATION.md に従います。

<a id="d08"></a>

## D08 — 作成日のしるしとメモの変更日時を分ける

### 初版で扱う意味

日付印は createdAt に基づく「残した日」です。並び順に使う updatedAt は、題名・本文・先頭固定を含むメモ全体の変更時刻です。カードが並び替わっても作成日印は変更日へ置き換えません。並び順の説明が必要な場所では「先頭に留めたメモを先に、それぞれ変更の新しい順」と伝えます。更新情報を表示する場合は「変更日」と呼び、本文の編集に限定した日時だと説明しません。

表示は YYYY.MM.DD と「朝／昼／夕／夜の余白」を引き継ぎます。現在の時間帯境界は朝5:00〜10:59、昼11:00〜15:59、夕16:00〜18:59、夜19:00〜4:59です。不正な日時から仮の日付や「夜の余白」を作らず、表示を省いて説明できる状態にします。

重要な情報は小さく薄い日付だけに押し込みません。必要な読み上げは「作成日 2026年11月26日」のように意味を含めます。復旧候補の更新情報は作成日印と区別し、D13 の比較でどの日時かを明示します。

### R37：初版の制約

現行の保存モデルには作成時のタイムゾーンがなく、日付印は閲覧時の端末のタイムゾーンで表示されます。旅行や端末設定の変更によって、同じ createdAt の日付や時間帯が変わり得ます。

**今回の初版では、このためだけの自動スキーマ移行を実施しません。** 作成地が分からない既存メモへ、今いる場所のタイムゾーンを「作成時」として書き込みません。初版のサポート説明では、必要な場合に「日付印は、端末の現在の時刻設定で表示されます」と案内できます。

### 将来仕様：作成時のしるしを保持する

将来は、新たに作成したメモから「作成時の現地の日付と時間帯」を保持する方向とします。以下は移行設計のための情報モデル案であり、今回の Note 型に追加する指示ではありません。

| 情報 | 役割 |
|---|---|
| createdAt | 既存の UTC の瞬間。並びや比較の基礎として保持 |
| 作成時の IANA タイムゾーン | 取得できた時だけ記録し、地域名を推測しない |
| 作成時の UTC オフセット | 分単位。UTC より東を正とするなど符号を明文化 |
| 作成時の日付印 | 現地の日付と朝／昼／夕／夜の区分を記録し、後日の時刻設定で変えない |
| 記録の由来と版 | 新規作成時に取得した値か、作成時情報のない旧データかを区別 |

固定した日付印を何から再計算するかを曖昧にしません。作成時のしるしを保存する方式を採るなら、その記録を表示の基準とし、タイムゾーン規則の将来更新だけで書き換えません。題名、本文、先頭固定の変更でも日付印を変えません。

移行を実施する将来の作業では、少なくとも次を満たす必要があります。

- 旧データは「作成時の地域は不明」のまま読める。現在地を過去の事実として補完しない。
- metadata のない旧メモの表示規則を定義し、既存本文・ID・日時を一括で書き換えない。
- 保存の検証、復旧候補、journal、ネイティブ予備保存、読み戻しが新しい情報を保持できる。
- 旧バージョンが新しい情報を読む・保存する場合の互換性を確認する。
- 日付境界、夏時間の境界、東京・ホノルル・ロンドン、タイムゾーン取得不能を確認する。
- 利用者が過去の地域を指定する機能を将来設ける場合は、本人が明示的に選び、原本を保つ。

## D09 — 文字を小さくする前に、余白と役割を整理する

### 書体の役割

題名・本文・短いブランドコピーは明朝系を基点にします。検索、ボタン、件数、保存状態、復旧説明、アプリ情報の実用的な説明は sans-serif を基本にします。全要素へ一律に明朝や広い字間を適用しません。

実際の iOS で使われたフォントと代替時の表示を確認します。フォント名を CSS に列挙しただけで、そのフォントが提供されるとは判断しません。書体のためだけに大きな外部フォントを追加する前に、端末内の書体で成立するか確認します。

### 文字の開始値

以下は標準倍率での仮目標です。CSS px の数値であり、Apple が一律に義務付ける pt 値や、今回測定した完成値ではありません。

| 役割 | サイズの開始値 | 行間の開始値 | 補足 |
|---|---:|---:|---|
| 編集・読み返しの題名 | 22〜26px | 1.4〜1.65 | 全文へ到達可能。長文や拡大で折り返す |
| 一覧の見出し | 17〜18px | 1.5〜1.65 | 原則2行から比較 |
| 入力本文 | **18px を基点に維持** | 1.85〜1.95 | 現行2.05とも比較し、窮屈にしない |
| 縦書き本文 | 18px を基点に17〜19pxを比較 | 1.95〜2.15 | 縦書きでは列間隔として確認 |
| 操作名 | 14〜16px | 1.45〜1.65 | sans-serif、名前を切らない |
| 日付・件数・保存状態 | 12〜13px | 1.45〜1.7 | 小ささと薄さを重ねない |
| エラー・復旧の説明 | 14〜16px | 1.6〜1.8 | 文章と次の操作を読み取れること |

本文の字間は現行0.024em付近から比較し、入力時は0.01〜0.024em程度も候補にします。欧文や URL、実用ラベルには広い字間をそのまま継承しません。縦書きの字間も、短い日本語だけで決めず混在文字で確認します。

### 横幅と余白

既存の外側21px＋紙内21pxという左右余白では、境界線を含めると375px幅の本文領域は約289px、390pxでは約304px、430pxでは約344pxになるコード上の概算です。18px＋0.024emを全角一文字の目安として割ると約15.7／16.5／18.7字です。実フォントの字幅、禁則処理、描画結果を測った値ではありません。

入力時の紙内余白を13px付近へ調整すると、375pxで本文幅は約305pxになります。文字を小さくする前にこの差を比較します。外側の余白や Safe Area まで失わせる必要はありません。

余白は4／8／13／21／34／55／89の既存スケールを起点にし、すべての境界へ大きい値を積み重ねません。日付→題名→本文の間隔は役割で決め、保存演出の透明な箱を余白として使いません。

### 固定コピーと本人の文章

アプリが書く短いブランドコピーは、必要なら表示用の行配列で改行を調整します。通常サイズで「る。」「こと。」だけが孤立する配置を避けます。ただし文字拡大時には折り返しを許し、明示改行のために横へはみ出させません。

本人の本文には同じ整形を適用しません。歌詞・詩の行頭空白、空行、短い行は意図の一部として扱います。読みやすさのための表示上の折り返しと、本人の改行を混同しません。

<a id="d10"></a>

## D10 — 文字・操作と、紙の装飾を別の層にする

### 色の契約

読ませる文字は原則4.5:1以上を設計目標にします。本文だけでなく、入力案内、日付、保存状態、リンクも対象にします。文字の色の alpha と親の opacity を重ねて、意図せず薄くしません。装飾の淡さを文字へ継承させず、透明度の責任を一か所へまとめます。

| 意味 | 色・表現の方針 |
|---|---|
| 主本文 | 墨。原文が最初に読める |
| 補助情報 | Faded Ink などの役割別色。必要なコントラストを満たす |
| 操作 | 文字、形、フォーカスで操作と分かる |
| 先頭固定 | 金は補助。選択状態を形と読み上げでも伝える |
| 保存中・保存済み | 静かな墨系。ただし読める濃さ |
| 保存失敗・削除 | 朱系の状態を独立させ、文章で意味を伝える |
| 復旧・確認中 | 状態名と次の操作。色だけで危険度を区別させない |

主な色の出発点は墨 #1F1B18、補助 #5F5750、朱 #B14A36、金 #C9A646、紙 #FBF6EA などの既存パレットです。この組合せを記載しただけで、すべての文字や線がコントラスト確認済みとは扱いません。テクスチャ・透明度・状態・フォーカスも含む実際の背景で確認します。

生成されない Tailwind の透明度クラスは、正しく生成される任意値または意味別トークンへ置き換えます。無効だった薄い色を一律に有効化して終わらせず、最終色を役割ごとに決めます。保存エラーは通常の薄い保存表示に上書きされない専用状態とします。

### 紙面の層

| 層 | 担当 | 避けること |
|---|---|---|
| 背景 | 月、紙の地、全体の色 | 入力するたびに質感を変える |
| 紙の装飾 | 繊維、色ムラ、紙端 | テキスト選択や操作を受け取る |
| 文書 | 題名、本文、カーソル、選択 | filter や紙端の切抜きで内容を欠かす |
| 操作と通知 | 戻る、保存、削除、復旧、フォーカス | 紙の子全体に掛けた clipping や配置指定へ巻き込む |

装飾は pointer-events:none 相当とし、通常フローの必要な余白を占有させません。紙面の「直下すべて」に position:relative!important を掛けるような指定を使いません。SaveAfterglow のような位置を持つ装飾は専用の層で管理し、保存前後で日付・題名・本文が動かないようにします。

clip-path は紙端の装飾へ限定するか、操作のフォーカスが明確に見える内側・外側の別要素へ分けます。全画面のダイアログや固定操作は、装飾の clip / filter / transform を掛けた親に依存させません。

監査基準の紙面本体は filter:none で、削除ダイアログも editor-paper の外です。現在の削除ダイアログが filter に巻き込まれていると確認したわけではありません。今後の構造変更でその条件を持ち込まないための契約です。

長文に合わせて紙を伸ばす場合、縦方向の percentage を使う紙端 polygon をそのまま拡大しません。高さ10,000pxの1%は100pxです。紙端の乱れが本文まで深く入らない独立した装飾にします。

### 動きと負荷

画面遷移や保存後の演出は、入力・タップ・画面移動を待たせません。通常は既存の200〜400ms程度の柔らかな遷移を比較の起点にし、減らす設定では不要な移動・拡縮・繰り返し演出を止めます。

React の再レンダーを、紙テクスチャ全体の再描画と同一視しません。長文の入力遅延は実機で layout、paint、保存処理を分けて調べます。CSS の集約と状態の所有範囲は IMPLEMENTATION.md の段階に従い、新しい phase CSS を追加し続ける方法で競合を隠さないでください。

## D11 — 大きな文字と読み上げでも、同じ操作を完了できる

### 文字拡大

標準・大きめ・200%相当で、作成、検索、読み返し、編集、先頭固定、削除、復旧、アプリ情報を確認します。OS の Dynamic Type へ追従する経路を実機で確かめます。単に px を rem へ替えたことや、ブラウザのズームだけを確認したことを Dynamic Type 対応完了とは呼びません。

OS の設定へ十分に追従できない場合は、簡単なアプリ内の文字サイズ設定で必要な倍率を提供する案を条件付きで採用できます。その場合も本文だけでなく、操作名、状態説明、復旧画面、ダイアログを対象にします。設定を増やすこと自体を目的にしません。

- 横並びの操作とメタ情報は必要に応じて縦に並べます。
- ラベルを縮小して一行へ押し込みません。省略した操作名だけで判断させません。
- ダイアログと比較画面には可視領域に応じた高さ上限とスクロール経路を用意します。
- 本文、エラー、確定・キャンセルのすべてへ到達できることを確認します。一画面へ全要素を収めることは条件にしません。
- 本文の横幅や縦書きの使用可能な高さを再計算し、前の座標のために内容を切りません。

### VoiceOver とフォーカス

カードの名前は、本人の題名または本文由来の識別見出しに、必要な作成日・固定状態を簡潔に添えます。全カードを「名のない余韻、読み返す」にしません。既に同じ情報を名前に含めた子要素を、重ねて読み上げない構造にします。

画面を開いた時は新しい画面の見出しや適切な入力へ、戻った時は D06 の元のカード・操作へフォーカスを移します。非同期の保存成功や一覧の並び替えが、利用者の入力位置を奪わないようにします。

通常の保存中・保存済みを短い入力の区切りごとに繰り返し通知しません。成功通知をまとめるか静的な確認へ寄せ、失敗・競合・復旧待ちは確実に伝えます。同じエラー内容を再レンダーのたびに読み上げ直しません。

ロゴ、円相、月、紙端、区切り線などは、意味を持つ見出しと重複しないよう装飾として扱います。「このアプリについて」や外部へのリンクは操作として区別できる名前にします。

### キーボードとダイアログ

44×44 CSS px はこのプロジェクトの操作領域の設計目標です。「すべての Apple 審査で一律必須の最小値」として説明しません。フォーカスリングは紙形状で切らず、外部キーボードの Tab、iOS のフルキーボードアクセスで現在位置を確認します。

削除や復旧の確認では、名称と説明を持つ dialog、適切な初期フォーカス、フォーカスの循環、キャンセル時の復帰を保ちます。現在の削除確認にある Escape とフォーカス処理は退行させません。背景の操作へ誤って到達させず、閉じる方法を一つのジェスチャーだけに限定しません。

## D12 — 保存状態は、いま表示している変更に対して伝える

本節は利用者への表示契約です。データの版比較、書込み順序、リトライ、競合判定、ネイティブ予備保存の実装は IMPLEMENTATION.md に従います。

画面上の状態は、少なくとも「現在の編集内容」「本体へ保存できた内容」「端末内の予備保存へ反映できた内容」の関係から決めます。画面の再入場やコンポーネントの初期状態で保存エラーを消しません。

本体へ保存できた版は、本体への書込み成功を確認した内容、または現存する本体との一致を確認して明示的に採用した版です。端末内の予備保存の候補や未保存の候補を選択しただけでは、本体保存済みになりません。予備保存にある候補を選んでも本体への書込みに失敗した場合は、現在の変更の保存失敗として案内します。

| 状態 | 主に表示すること | 操作・継続 |
|---|---|---|
| 入力後、保存を待っている・処理中 | 保存中 | 入力や通常の画面移動を続けられる |
| 現在の変更の本体保存が失敗 | 最新の変更を保存できませんでした | 再試行と、文章を取り出す経路 |
| 本体は現在版、予備保存のみ失敗 | 最新の変更は保存済みです。端末内の予備保存を更新できませんでした。 | 予備保存の再試行 |
| 候補の確認が必要で保存停止 | 内容を確認するため、保存を止めています。 | 内容を確認する |
| 起動・復帰時の安全確認中 | 保存内容を確認しています。 | 変更を止める操作にも状態を反映 |
| 保存内容の読込み・安全確認に失敗 | 保存内容の安全確認ができませんでした | もう一度確認する。不存在とみなして上書きしない |
| 現在版の必要な保存が成功 | 保存済み | 短く表示した後、静かな通常状態へ戻す |

### 優先度と同時表示

現在の変更が本体に保存されていない時、以前の予備保存の警告を「メモ本体は保存されています」という主文で重ねません。未保存・保存停止の理由を優先し、必要なら「以前に保存した内容は残っています」と版の違いを明示します。

本体保存の成功後に予備保存だけ未更新であれば、その状態を改めて表示します。成功を知らせた後に古い非同期結果が届いても、表示中の版と関係のない結果へ戻しません。

失敗・競合・確認待ちには、読める大きさとコントラストを持つ主文を一つ用意します。原因が同じままの「再試行」だけを繰り返させず、D13 の解決先へ進めます。警告を閉じただけで保存済みに変えません。

### 画面移動と案内

編集、読み返し、一覧のどこにいても、現在の未保存内容が存在する事実を失わせません。対象のメモへ戻れることも必要です。通常の成功演出は短くできますが、未解決の失敗は時間だけで消しません。

確認中に作成・編集・削除・候補確定が禁止される場合は、見た目と支援技術にも busy / disabled 相当を伝えます。現在保持している文章の閲覧やコピーは、保護上可能な範囲で残します。

「コピーしました」はクリップボードへのコピー成功だけを表します。コピー、画面の描画、一定時間の経過を保存成功と扱いません。コピーに失敗した場合は成功表示を出さず、選択できる原文を表示します。

<a id="d13"></a>

## D13 — 復旧は内容を見比べ、未保存の文章を取り出せる

### 通常画面からの入口

保存停止の短い主文と「内容を確認する」操作から、比較専用の画面または十分な高さとスクロールを持つ領域へ進みます。長い説明、三つの候補、複数の確定操作を、上端固定の一つの警告へ詰め込みません。

通常画面にも保存停止中であることを残し、比較を閉じただけで通常保存を再開しません。候補を確認するだけでは保存内容を変えません。

候補の「選択」「表示」「本体への保存完了」は別の状態です。確定操作を押したという事実だけで「保存済み」にせず、D12 の本体保存の条件を満たしてから完了を知らせます。

### 比較に必要な情報

| 情報 | 表示の契約 |
|---|---|
| 候補の呼び名 | 「この画面の未保存の内容」「保存先で見つかった内容」「端末内の別の候補」など、本人が理解できる名称 |
| 件数 | 0件も明示する。全件削除済みの候補を「何もないから無視」と扱わない |
| 更新情報 | 実際に確認できる日時と、その意味。未知のものを推測で最新と呼ばない |
| 違い | 件数差、異なるメモ、題名と本文の短い抜粋 |
| 全文 | 必要な各メモを原文で読み、コピーできる |
| 確定操作 | どの内容を残し、他のどの内容へ影響するかを説明してから実行 |

「localStorage」「native」「journal」など内部の名前だけで選ばせません。件数や日時だけで同一と判断せず、内容の違いを確認できるようにします。自動で候補を混ぜない既存の保護を維持します。

「この内容を残す」のような最終操作には、対象候補を明示します。必要な他候補が保護されるか、利用者の確認で破棄されるかを実装に合わせて説明します。「破棄しない」と表示しながら、未確認の候補を上書きすることはできません。

### 保護候補が満杯の場合

通常の競合と分けて、「保護している候補がいっぱいのため、まだ保存できません」と理由を伝えます。同じ保存ボタンを押し続けるだけの画面にしません。

現在の未保存の文章を保持したまま、候補の確認、必要なメモのコピー、利用者が不要と確認した候補だけの整理、選んだ内容の保存まで進める経路を用意します。自動で最も古い候補を削る処理は採用しません。

候補の整理は通常の本文編集に紛れ込ませず、何が消えるかを具体的に確認します。保存できなかった場合は現在の文章と保持対象の候補を残し、整理が完了した範囲と保存が未完了であることを分けて示します。整理後に書込みが失敗した場合を、すべて変更なしと案内しません。比較画面を作っただけで、満杯からの解決を完了としません。

### 容量不足・保存先を利用できない場合

容量不足の文言は「メモの保存領域が足りないため、最新の変更を保存できませんでした」のようにします。「不要なメモを削除すれば必ず解決する」「写真を消せば直る」とは案内しません。現行方式では、削除を確定する書込みも容量不足で止まる場合があるためです。

最低限、現在の題名と本文を読める・選択できる・コピーできる出口を設けます。本文のコピーは原文のままとし、題名がある場合はそれも取り出せます。クリップボード API が使えない時は、読み取り専用の原文から手動選択できるようにします。

一般向けの全メモ一括書出し・インポートは、今回の救済契約とは別の追加機能です。未実装の書出しを案内に載せません。候補全体のファイル書出しを採用する場合は、保存形式・受入条件を追加してから実装します。

### 描画障害の画面

表示に問題が起きた場合の画面は、「再読み込み」だけにしません。保持できた最新の題名・本文を読み取り専用で示し、コピーへ進めるようにします。描画で壊れた範囲の外に保持する方法は IMPLEMENTATION.md に従います。

どの版まで保持できたかが不明なら、「すべて保存されています」と表示しません。再読み込みで未保存内容を失う可能性がある時は、その扱いを伝え、先に取り出せる順序にします。エラーを契機に、競合判定を無視した強制保存や保存データの初期化をしません。

375×667 相当、200%相当、三候補、保護枠満杯でも、候補の全文確認・切替・キャンセル・確定に到達できることを確認します。通常の保存待ち、保存失敗中、競合中のそれぞれで障害時の救済を確認します。

## D14 — 削除する内容と取り消せる範囲を伝える

確認の題名は「このメモを削除しますか？」、操作は「キャンセル」「削除する」とします。本文・題名の短い識別情報を添え、どのメモかが分かるようにします。「手放す」だけで破壊的な操作の意味を伝えようとしません。

確認画面は小さい画面と大きな文字でスクロールでき、必要ならボタンを縦に並べます。初期フォーカスはキャンセルを基本とし、既存のフォーカス循環、Escape、キャンセル後の元の削除操作への復帰を維持します。

### 取り消し

初版はゴミ箱を追加せず、現行の「直前1件、10秒、現在の起動中」という条件を基点にします。本文の案内は、少なくとも直前1件と時間制限を明示します。

> 削除後10秒間は、直前の1件を元に戻せます。

アプリを終了・再起動すると取り消せないことは D16 の説明にも記載します。バックグラウンドへの移行とプロセスの終了を混同せず、実際のタイマーと案内を一致させます。

Undo は作成 CTA やホームインジケーターと重ならない位置へ置き、読み上げでも発見できるようにします。連続削除で対象が入れ替わることを確認し、どのメモが戻るか不明にしません。VoiceOver などで猶予が足りない場合は、時間や一時停止の扱いを調整して文言も更新します。10秒という現状値だけを理由に、操作できない状態を合格にしません。

### 削除の保存に失敗した時

一覧から一時的にカードを外す実装であっても、保存の確定に失敗した時は「削除を保存できませんでした」と知らせます。「削除しました」だけで終わらせず、以前の本文と現在の状態を確認できるようにします。

取り消し後も、必要な保存結果に基づいて状態を表示します。容量不足からの脱出を削除だけに依存させず、D13 の原文を取り出す経路へ進めます。削除・取り消し後の一覧位置とフォーカスは D06 に従います。

「保存済み」「コピーしました」「削除しました」はそれぞれ実際の結果に対応させます。復旧の確定ボタンは、どの候補を対象にするかが分かる文言へ補います。危険な操作を「進む」「OK」だけで確認しません。

### 一般向けの説明文案

以下は、対応する実装と受入確認が完了した後に、アプリ情報やサポートへ載せるための文案です。未実装の機能を提供済みとして公開しないでください。

#### はじめる

> 「メモを書く」から、すぐに本文を書き始められます。タイトルは付けなくても大丈夫です。入力した内容は、この端末に自動保存されます。

#### 読み返す・直す

> 一覧のメモを開くと、縦書きで読み返せます。続きを左へ読み進め、「編集する」から文章を書き足したり直したりできます。

条件付きの横書き切替を実装した場合だけ、その選び方を追加します。

#### 大切なメモを先頭へ

> 「先頭に留める」を選ぶと、金のしるしが付き、一覧の先頭のグループに置かれます。固定したメモとそのほかのメモは、それぞれ変更の新しい順に表示されます。題名や本文の編集に加え、しるしの付け外しも変更として扱います。

#### 保存について

> メモは、この端末に保存されます。クラウド同期はありません。端末内の予備保存は、同じ端末で内容を復旧するためのものです。別の端末や機種変更後に必ず戻せる仕組みではありません。

> 保存できない案内が出た時は、最新の変更がまだ残せていないことがあります。表示された操作で確認し、必要に応じて題名や本文をコピーしてください。アプリの削除やデータの消去をすると、メモを取り戻せなくなる場合があります。

端末や OS 自体のバックアップの有無まで、アプリの説明だけで断定しません。「絶対に消えない」「必ず復元できる」といった保証を加えません。

#### 削除について

> 削除後10秒間は、直前の1件を「元に戻す」で取り消せます。アプリを終了・再起動した後は取り消せません。必要な文章かを確認してから削除してください。

実機評価で猶予時間や停止条件を変更した場合、この説明も同時に更新します。ゴミ箱を実装していなければ、その存在を案内しません。

#### 問い合わせについて

> GitHub Issues への投稿は公開されます。メモの本文、個人情報、他の人の情報は書かず、困っている操作とアプリのバージョンをお知らせください。

実際の問い合わせ先を別の方法へ変えた場合は、それに合わせて書き直します。

## 画面横断の確認メモ

詳細な手順と結果記録は [ACCEPTANCE.md](ACCEPTANCE.md) に集約します。本書の設計を確認するための最小セットは次のとおりです。

| 原文の種類 | 設計上の確認 |
|---|---|
| 無題の本文1行 | 命名せず完結し、一覧で同じ一文を重複表示しない |
| 長い題名と2,000字程度の日記 | 題名・本文とも全文を編集・読書できる |
| 200字以上の URL と日本語 | 画面からはみ出し続けず、コピーでは文字列が同じ |
| 10項目の箇条書き | 番号、記号、字下げ、改行を保つ |
| 空行を含む20行程度の歌詞・詩 | 行分けを自動で結合せず、途中編集後も同じ原文 |
| 日本語・2026・3:30・欧文・絵文字 | 縦書きの向き、Unicode、抜粋、選択に破綻がない |

各文章で、作成→保存→読み返し→途中編集→一覧・検索へ復帰→コピーを確認します。通常表示だけでなく、標準／大きめ／200%相当、375×667相当とより大きい iPhone、キーボードの有無、VoiceOver、動きを減らす設定で確認します。

異常時には、保存失敗後の画面往復、古い予備保存警告と新しい本体保存失敗、未保存中の描画障害、三候補の比較、保護候補満杯、容量不足中の削除を確認します。正常画面だけ整えて、異常時に本文へ届かなくなる状態を残さないでください。
