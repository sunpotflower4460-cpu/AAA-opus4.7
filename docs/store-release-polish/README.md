## 今回、完成させる体験

1. 題名なしのひとことから書ける。
2. 入力した文字、改行、空白がそのまま残る。
3. 本文の冒頭から末尾まで読める。
4. 今の文章が保存済みか分かる。
5. 読み返し・編集・検索の間を移動しても、文章や元の位置を見失わない。
6. 保存を安全のために止めた場合も、本文を取り出し、解決へ進める。

和紙・明朝・墨・金・月の表現を保ち、本文と操作が読みやすい強さへ整えます。短い買い物メモ、日記、書きかけの歌詞や詩を同じ場所に置けることが基準です。

## 初版の範囲

### 現在の方針を維持するもの

- iPhone、portrait。iPadと横向きへの対応拡大は今回の必須条件にしない。
- 無料、広告なし、Premiumなし、アカウントなし、クラウド同期なし。
- 現行のReact / TypeScript / Vite / Tailwind / Capacitor 7を基盤にする。
- 本体保存、journal、競合検知、復旧候補、native予備保存の既存保護を維持する。
- 日本語UIを完成させる。英語文言の存在だけで英語UI対応済みと扱わない。
- 記録済みのiosプロジェクトを使う。通常作業でiosを消して再生成しない。

### この設計に含む改善

文字の配置・可読性、キーボード、縦書き、保存表示、復帰時の版比較、未保存本文の救済、復元の解決導線、未操作下書き、検索・Unicode・戻り先・読み上げ、アプリ内の情報とポリシー導線を含みます。

未保存文章や復元候補を、利用者の明示操作で表示・コピー・必要に応じて端末へ書き出すことは、ここで扱うデータ保全の改善です。第三者へ送信する機能ではありません。一般的なクラウドバックアップ、共有サービス、全データのimport機能は別の機能として扱います。

### 条件付き・次期に分けるもの

| 項目 | 初版での扱い | 判断の記録 |
|---|---|---|
| 横書きでの読み返し切替 | 本書の日本語版では条件付き。次段階の[日英対応](../multilingual/DESIGN.md)では完成条件として必須 | 縦横両方を確認。本文やUI言語から既存の読み方向を自動変更しない |
| 作成時タイムゾーンの保持（R37） | 将来仕様を定義し、初版のスキーマ移行は保留 | 現在地換算という現挙動を記録。既存メモの作成地を推測しない |
| 保存基盤の全面移行 | 実機容量・性能の測定と安全な移行計画が必要な場合に別の変更単位で判断 | journalや予備保存を取り外して見かけ上の成功を作らない |
| 永続的なゴミ箱・一般的なエクスポート/インポート | 今回の必須機能にはしない | 10秒・直近1件のUndoと、失敗時の文章救済をまず確実にする |
| タグ、フォルダ、カレンダー、AI、同期、課金、広告 | 今回追加しない | 現在の検索と内容の識別、先頭固定を磨く |

## 初版で採用する判断

レビューには選択肢も含まれていたため、実装が分岐しないよう次を既定方針とします。

| 判断 | 採用する仕様 | 理由 |
|---|---|---|
| 作成操作の名前 | 「メモを書く」に統一 | 初見で動作が分かる。「言葉を置く」はブランドコピーで使える |
| 題名 | 「タイトル（任意）」 | 一文だけでも成立させる |
| 編集操作 | 「編集する」 | 修正と書き足しの両方を含む |
| 戻る | 「一覧へ」「検索結果へ」「読み返しへ」 | 次の行き先を示す |
| 無題の一覧 | 最初の非空行を識別用に使い、保存タイトルは空のまま | 大量の無題を見分け、原文を自動命名しない |
| 無題の読み返し | 大きな代替題名を加えず、本文を主役にする | 短い言葉をそのまま読める |
| お気に入り | 現行の先頭固定を保ち、その意味を伝える | 初版の変更量を抑え、既存の使い方を維持する |
| updatedAt | 題名・本文・印を含むメモ全体の変更時刻として維持し、同群内は「変更の新しい順」と説明する | 復旧処理が参照する既存の時刻の意味を保つ。本文専用の時刻は追加せず、日付印は作成日を表す |
| 入力本文 | 現行の明朝18pxを比較の基点にする | 先に内側余白・行間を調整する。UI操作文には読みやすいsansを使う |
| 読み返し | 縦書きの文書フロー＋連続横スクロール | 親flexの軸・装飾のoverflow・不必要なsnapを整理する |
| 救済 | 表示例外や保存失敗でも最新本文へアクセスできる | 保存を止める保護と、利用者が解決する操作をつなぐ |

文字サイズ、余白、本文4〜6行などは比較のための目標値です。特定のiPhoneで確認済みの値として扱わず、文字拡大・日本語キーボード・長文で確定します。

## 進捗と証拠

[ACCEPTANCE.md](ACCEPTANCE.md) を項目単位の記録場所にします。各Rを未着手・対応中・実装済み未検証・自動確認済み・実機確認済み・外部条件待ち・初版保留などに区別し、確認したコミット、環境、操作、結果を残します。

「設計を入れた」「ビルドが通った」「jsdomが通った」「実機で表示を確認した」は別の状態です。見ていない画面や動かしていないApple環境を完了扱いにしません。

監査時の証拠は次の範囲です。

- 第1回：型検査・lint・通常ビルド成功。一時設定で既存21ファイル169テスト成功。追加3ケースで現行の問題を再現。
- 元のnpm run check：Cloudflare Vite pluginによるuv_interface_addressesエラーでテスト起動不可。全体成功とは扱わない。
- 第2回：追加2ファイル4テスト。現行の問題3ケースとIMEの基本正常経路1ケース。
- 保存容量：合成localStorageモデルの文字列長を測定。実端末の容量上限ではない。
- 日付印：実関数でタイムゾーンを比較。
- 実ブラウザ描画、iPhone、Xcode Archive、TestFlight、App Store Connect：未確認。

監査用の問題存在アサーションを、そのまま修正後の回帰テストにしません。実装後は望ましい動作を検証するテストへ置き換え、既存のデータ保護テストも通します。

## 外部条件が必要な作業の扱い

実装・自動確認・文書更新・レビュー可能な差分の準備は進めます。Appleアカウント、署名、実機、実際に管理する問い合わせ窓口などが必要な箇所だけ、未確認条件として具体的に残します。架空の連絡先や公開URLは作りません。

この文書群の追加は、App Storeへのアップロード・審査提出・配信開始やCloudflareへの公開を自動的に許可するものではありません。外部操作は、その時点の利用者の指示と利用可能な権限に従います。ブランチ保護やCIの条件も維持します。
