# Phase 29 — 「間」と「所作」による UI/UX Polish

## 目的

残心の UI/UX を、単に「和紙テクスチャのある和風 UI」から、
**余白・紙片・墨・読む向き・触れたときの所作まで一貫した、残心固有の体験**へ進める。

今回の方針は、和柄や装飾を増やすことではない。
Phase 21〜28 では和紙感を強めた後に、グレー化・虹色化・検索欄の見切れなどを何度も補正しているため、
Phase 29 では質感をさらに足さず、次の四つを中心に磨いた。

1. **間（Ma）** — 余白と階層の呼吸
2. **所作（Shosa）** — タップ、フォーカス、押下、画面遷移の作法
3. **紙片性** — 角丸カードではなく「言葉が置かれた紙」として見せる
4. **信頼できる UX** — 表示と実挙動、キーボード操作、タッチ領域を一致させる

---

## 1. 画面全体 — 見えない「間」の背骨

`AppShell` に `zanshin-ma-axis` を追加した。

- 画面左側に、ほとんど気づかないほど薄い縦の基準線を置く
- 途中にごく小さな金点を一つだけ置く
- 装飾として主張させず、ホーム・読む・書く画面に同じ縦方向の呼吸を通す
- モバイルではさらに薄くし、内容を邪魔しない

これは罫線ではなく、床の間の柱や掛け軸の軸のような「空間の基準」を狙ったもの。

---

## 2. ホーム — 「カードの集合」から「紙片が残る場所」へ

### タイトル

- 円相マークを 30 → 32px
- 「残心」を 24 → 26px
- 字間を少し広げ、アプリ名を UI ラベルではなく題字に近づけた
- ヘッダー末尾には長い区切り線ではなく、55px の短い金の余韻だけを置く

### タグライン

従来の大きく丸いカード感を弱め、短冊に近い形へ。

- 強い角丸をやめる
- 四辺を完全な直線にせず、手漉き紙程度のごく小さな揺らぎを残す
- 影を弱める
- 既存の和紙テクスチャは増量しない

---

## 3. 検索 — generic pill UI をやめる

検索欄は操作性を保ちながら、現代的な丸い pill から「細い紙札」へ寄せた。

- 高さ 52px
- 非対称な紙端
- 左端にごく薄い藍の縦気配
- フォーカス時だけ藍が少し濃くなる
- クリアボタンを 44 × 44px に拡大
- タッチ端末では hover の浮遊を出さない

検索は強い機能 UI ではあるが、残心の紙世界から急に別アプリへ出ないようにした。

---

## 4. メモ一覧 — 「角丸カード」を卒業

メモカードは、均一な SaaS カードではなく紙片として認識できるように再調整。

- 非対称な角
- ごく小さい紙端の揺らぎ
- 右下に折れ目を連想させる極小の紙角
- 左の一本線は「カードの罫線」ではなく紙に残る背骨として維持
- お気に入り時だけ金が残る
- desktop の hover は 2px だけ浮く
- touch では hover を無効化
- active では少し沈み、紙に指が触れた感覚を返す

### CSS 競合対策

Phase 28 には `.zanshin-note-card > * { position: relative !important; }` があるため、
紙の背骨をカード直下から内部の相対コンテナへ移動した。

見た目の修正だけでなく、過去 Phase の上書き規則に負けない構造へ整理している。

---

## 5. FAB — 「＋ボタン」から小さな硯 / 印へ

「言葉を置く」ボタンは機能上は FAB のままだが、見た目の文法を変えた。

- 完全な円をやめる
- 墨色の小さな塊として扱う
- 内側に非常に薄い金の輪郭
- 光沢を強くせず、硯・印・墨石のような重さを出す
- desktop hover と touch active を分離

ボタンを和風に“飾る”のではなく、**置かれている物体の意味そのものを変える**方向。

---

## 6. 書く画面 — 操作部品と保存フィードバック

### ヘッダー操作

一覧・読む画面と同じ `zanshin-screen-bar` / `zanshin-nav-button` 文法へ統一。

- 戻る
- 大切な余韻
- 削除

のタップ領域と角の扱いをそろえた。

お気に入り ON 時は、ボタン自体を派手に塗らず、右下に小さな金点が残る。

### 保存 UX の実挙動修正

従来はエディタ側が入力後 **320ms** で「保存済み」を表示していた一方、
実際の `App.tsx` の localStorage autosave debounce は **500ms** だった。

つまり理論上、実保存より先に「保存済み」が出る瞬間があった。

Phase 29 では保存表示を **650ms** 後に変更し、実保存より先に成功表示を出さないようにした。

- 実保存: 500ms debounce
- 保存済み表示: 650ms
- 保存済みの余韻: 1200ms

見た目よりも「UI の言葉が嘘をつかない」ことを優先した。

---

## 7. 削除 UX — 文言と実装の矛盾を解消

従来の確認文は、

> 削除すると、あとから戻すことはできません。

だったが、実装には **10秒の Undo** が存在する。

Phase 29 では、

> 削除したあとも、しばらくは元に戻せます。

へ変更。

さらに削除モーダルに以下を追加。

- `aria-describedby`
- 初期フォーカス
- Escape でキャンセル
- Tab / Shift+Tab のフォーカスループ
- キャンセルと削除のタップ領域を明確化
- 紙片らしい非対称形

---

## 8. 読み返し — 既存の縦書きを守る

Phase 19 から存在する `writing-mode: vertical-rl` は、残心の最も固有性が高い体験の一つなので維持。

Phase 29 では大きく変えず、

- 紙面の形をエディタと統一
- 横方向 overscroll を抑制
- proximity scroll snap を追加
- 金の区切りをわずかに整える

だけに留めた。

**「個性的にする = 新要素を足す」ではなく、既に強いものを主役として残す**判断。

---

## 9. Premium / 広告 — 脇役でも世界観を切らさない

### Premium Sheet

- generic な 21px 角丸モーダルをやめる
- タイトルの二重表示を整理
- 紙面に一本だけ金の導入線
- benefit box も小さな紙片へ
- CTA を 48px、補助操作を 44px 以上へ
- body scroll をモーダル表示中だけロック
- Escape 対応
- Tab / Shift+Tab の完全なフォーカストラップ
- 閉じた後は元の操作要素へフォーカスを戻す

### Restore Purchase

文字リンクだけだった復元操作を、見た目は静かなまま **44px のタップ領域**へ拡張。

### 広告枠

広告をメモと誤認させないことを優先し、破線・AD 表示は維持。
ただし完全な pill / round UI を弱め、残心の紙片文法へ合わせた。

---

## 10. Error Boundary — 障害時にも人格を消さない

従来は、

> 問題が発生しました / Something went wrong
> 再読み込み / Reload

という一般的な Web fallback だった。

Phase 29 では意味を曖昧にせず、

> 余白を、もう一度ひらきます。

という残心の言葉へ置き換えた。

英語補助文は残し、再読み込みボタンは 48px。
エラー時だけ突然別ブランドへ切り替わる感覚をなくした。

---

## 11. アクセシビリティ / 入力方式

- 検索 clear: 44 × 44px
- editor actions: 44 × 44px
- restore purchase: 44px 以上
- premium CTA: 48px
- hover 表現は `hover: hover` / `pointer: fine` のときだけ強化
- touch では hover の浮遊を抑える
- `prefers-reduced-motion` を引き続き尊重
- delete / premium dialog に keyboard focus management
- dialog close 後の focus restoration

和風の静けさを、操作性を犠牲にする理由にはしない。

## 今回、あえてしなかったこと

- 和柄を追加しない
- 赤・黒・金を派手に増やさない
- 桜・鳥居・麻の葉など説明的な日本モチーフを足さない
- 和紙ノイズをさらに強くしない
- 既存の月・円相を増殖させない
- 新しい画面や複雑な設定を増やさない
- 縦書き読み返しを横書きへ戻さない

残心の個性は「日本を説明する記号」ではなく、
**言葉を置き、離れ、あとから静かに読み返す所作**から生まれるべきだと判断した。

## 自己レビュー

### 和風らしさ

**向上。**
素材を増やさず、短冊・紙片・墨石・縦書き・間・金のしるしを同じ文法で揃えた。

### 個性

**向上。**
特に「縦書きの読み返し」「紙片としての一覧」「墨石のような新規作成」「保存後の余韻」が、一般的なメモアプリとの差になる。

### プロダクト品質

**向上。**
保存表示の時系列、削除 Undo 文言、focus trap、focus restoration、44/48px touch target など、見た目以外の信頼性も同時に改善した。

### 過剰装飾リスク

**抑制。**
Phase 21〜28 の反省から、テクスチャ強度は増やしていない。今回の差分は主に形、余白、階層、入力方式、状態表現。
